# 独立数据库蓝绿部署

## 范围

本次是从现有绿色部署过渡到蓝色部署。蓝色有独立 PostgreSQL、Redis、上传文件、技能包和知识库目录。保留绿色程序及原数据；回退时接受放弃蓝色期间新增的内部测试数据。算力平台开户、划转、扣费等外部事实不会随本地回退撤销，必须保留新环境记录并核对。

不得将两个 PostgreSQL 容器挂载同一个数据目录，不覆盖或迁移算力平台自身数据库。原 `sep-postgres`、`sep-redis`、`sep-ollama`、下载服务和其他站点继续保留。

## 操作入口

GitHub `Deploy to Production` 工作流增加以下操作。始终选择同一个待发布提交。`rehearse`、`stage` 要求该提交的 Quality Gates 成功；恢复操作不依赖重新通过质量检查。

| 操作 | 行为 |
| --- | --- |
| `rehearse` | 在线备份 SEP 单库，在隔离数据库中恢复、升级、逐表核对；不启动新版后台任务，不切流量 |
| `stage` | 指定演练输出的 `release_tag`，提前构建新版镜像，进入维护、排空并停止旧应用，重新迁移最新数据，启动新版等待验收 |
| `activate` | 指定原标签，验收完成后切换全部入口到新版 |
| `rollback` | 指定原标签，先隔离入口并排空停止新版，再恢复旧程序及原数据路径 |
| `status` | 查看对应候选状态，不输出环境变量、账号密钥或业务数据 |

`stage` 成功后网站仍为维护状态。新前端/后端仅绑定服务器 `127.0.0.1:13000/13001`，通过 SSH 隧道进行验收。不开放数据库和 Redis 的宿主端口。

该脚本仅处理第一次绿色到独立蓝色的过渡。蓝色激活后拒绝覆盖旧绿色容器；后续轮换需另行设计，不能执行旧的原位置部署脚本。

## 数据迁移与核对

1. 演练在新目录 `/www/sep/blue-green/<tag>/rehearsal` 创建新 PostgreSQL，复用原数据库的固定镜像，包含 pgvector。候选数据库网络隔离，不连接现有数据库网络。
2. 使用 `pg_dump -Fc` 导出原 `sep_prod`，恢复到空的新数据库。复制历史表、数据、索引、扩展和 Prisma 迁移记录，不创建算力平台账户。
3. 恢复使用 `--exit-on-error --single-transaction --no-owner --no-acl`。在候选集群创建专用应用账号，迁移使用候选管理员连接，业务应用使用受限账号。密码不输出、不提交 Git。
4. 读取原表的列清单，将每行原始列转为稳定排序的文本，记录行数及 SHA-256。恢复后和迁移后均核对原列内容；新增列不影响原列比较。
5. Prisma 迁移表允许新增成功记录，另核对全部迁移名称、成功状态和 SQL 校验和。接受相同 SQL 的 LF/CRLF 换行差异，拒绝其他 SQL 内容变化及未解决的失败迁移；不修改历史校验和。
6. 校验 11 张算力业务表和实际 pgvector 列、HNSW 索引。校验失败阻止后续步骤。
7. 正式 `stage` 在 `/www/sep/blue-green/<tag>/final` 建立全新副本，不使用已经被演练修改的数据。维护并停止旧应用后确认没有 SEP 数据库客户端、没有未完成队列，再记录源数据库内容摘要并重新导出。
8. 复制 `uploads`、`packages`、`knowledge` 到候选私有目录，逐文件比较大小和 SHA-256；未审查的符号链接阻止迁移。只读 tokenizer 等文件保持只读复用。
9. Redis 通过 RDB 恢复到新实例，保留独立初始备份，再启用并验证 AOF。旧 Redis 不清空、不重置。
10. 旧应用在候选运行期间保持停止且关闭自动重启策略，避免两套后台任务同时运行。回退完成健康检查后恢复原重启策略。

在线演练只比较同一份数据库备份恢复前后的结果，不将备份与仍在写入的原库作内容一致性声明。正式迁移在冻结后增加源库、恢复库、迁移库三方核对。

## 算力接入与验收

候选继承旧应用的必要配置和加密秘密，但不会默认继承旧模型凭证作为新算力集成。生产接入配置由服务器 `/www/sep/deploy/compute-integration.env` 提供，权限必须为 `600`，只接受 `COMPUTE_*` 原始键值，不加引号、不使用 shell 展开。算力平台未部署或正式配置未准备时，可以完成数据库演练，但 `stage` 的预检查会在维护前拒绝继续。

正式私钥放在 `/www/sep/secrets/compute`，候选只读挂载到 `/run/sep-compute`。私钥必须能被容器应用用户读取，不能通过聊天或 Git 交付。算力平台需部署对应接口并登记正式公钥、用途分组；本地开发密钥不能直接作为生产密钥。

先验证一家测试企业开户、三类凭证、目录、人民币报价、初始资金、实际调用和最终结算，再处理其他企业。已有企业需显式准备开户；新建表不会自动开户。开户成功后现有 Worker 会自动尝试完成连接及初始资金同步，不应把“准备”当作完全无外部副作用的检查。

开放访问前需在候选目录保存真实验收结果 `acceptance.json`：

```json
{
  "tag": "<演练输出的标签>",
  "data": true,
  "accounts": true,
  "billing": true,
  "client": true
}
```

只能在对应检查实际完成后填写，不能为了跳过验收提前写为 `true`。激活还会检查旧应用停止、候选健康、算力集成启用。Caddy 同时切换 Web、WebSocket、技能导入和视频参考上传后端，独立 AI 站点区块及其后配置原样保留。Next.js 构建时用 `SEP_API_ORIGIN=http://sep-blue-backend:3001`，避免新版前端仍代理旧后端。

## 故障与证据

维护前失败不停止旧程序。维护后失败先确认新版 Worker 停止，再启动原容器并恢复旧入口。停止失败则保留维护，禁止强杀或启动第二组 Worker。回退保留蓝色数据库和文件作为账务、开户排查证据，不自动删除。

每个候选目录的 `state.json`、`original-columns.json`、`restored-audit.json`、`migrated-audit.json`、`source-audit.json`（正式迁移）、文件摘要和 `backup-checksums.json` 作为验证证据。失败详情保存在权限受限的 `operations.log` 或 `restore-error.log`，不能直接公开原始日志或备份。

备份、Compose 生成文件和 `database-identity.json` 含私有数据或密码，全部仅在服务器私有目录保存，不上传 Actions artifact，不提交 Git。所有发布操作与既有部署共用 `/www/sep/.deploy.lock`。
