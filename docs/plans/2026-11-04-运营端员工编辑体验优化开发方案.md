# 运营端员工编辑体验优化开发方案

日期：2026-11-04
状态：已实现，自动化检查通过；待登录后视觉验收
范围：运营端员工新建与编辑

## 1. 背景与目标

运营端员工表单把头像地址、模型 ID、描述和系统提示词都作为普通表单字段，同时一次性展示全部可绑定能力。头像与模型已有更合适的统一配置路径；描述和系统提示词需要专业撰写，当前空白文本框增加了创建门槛；能力数量增长后，用户难以查找目标能力，页面也会被长列表撑长。

本次优化目标：

1. 员工表单不再手工输入头像 URL 或选择模型。
2. 头像使用现有头像风格管理能力，由平台默认风格和员工头像素材绑定负责。
3. 描述和系统提示词通过平台 AI 生成可编辑草稿，同时保留人工编辑能力。
4. 能力选择支持搜索、筛选、独立滚动和已选状态反馈，不改变能力绑定及优先级契约。
5. 不破坏历史员工、现有会话运行和旧客户端读取。

## 2. 当前实现与约束

- 新建页：`web/src/app/(platform)/admin/employees/new/page.tsx`
- 编辑页：`web/src/app/(platform)/admin/employees/[id]/edit/page.tsx`
- 能力列表由 `useAvailableCapabilities()` 获取，两页都在页面主体中直接渲染全部能力卡片，没有搜索或列表滚动边界。
- 头像风格管理页：`web/src/app/(platform)/admin/employees/avatar-styles/page.tsx`，支持平台默认风格、员工单独风格及批量同步。统一的是风格体系，每个员工仍可对应自己的素材形象。
- 员工运行时仍读取 `DigitalEmployee.systemPrompt` 和 `DigitalEmployee.modelId`。模型解析还会根据会话覆盖、订阅配置及企业 `FOLLOW_TEMPLATE` / `FORCE_DEFAULT` 策略决定最终模型。
- 市场和企业端使用员工描述；公开市场接口有意不返回系统提示词和模板模型。
- 工作区已有用户改动，实施时需基于最新文件增量修改，不能覆盖或回退现有编辑。

因此，本方案移除的是员工表单中的直接编辑入口，不在本轮删除数据库字段、历史值或运行时读取。模型策略和头像素材的后续彻底收敛另行评估存量数据及企业策略后处理。

## 3. 产品方案

### 3.1 头像入口

- 从新建、编辑表单移除“头像地址”输入及对应本地表单状态/提交字段。
- 员工新建后默认跟随平台头像风格；头像由现有员工素材绑定解析。
- 在表单中提供“头像风格管理”入口，跳转 `/admin/employees/avatar-styles`。创建完成后可在头像管理页为员工单独指定风格。
- 编辑已有员工时，保存其他字段不得把当前头像覆盖为空或触发 `custom` 风格。后端省略 `avatar` 时保持原头像及风格不变。
- 不删 `avatar`、`avatarStyle`、`avatarBindings` 等数据库字段，不清除现存自定义头像记录。

### 3.2 模型入口

- 从新建、编辑表单移除模型选择、模型列表请求和 `modelId` 表单状态/提交字段。
- 新员工沿用后端现有默认模型值；运营人员通过企业模型配置管理实际策略。
- 运行时继续兼容模板模型回退逻辑和历史员工 `modelId`。本轮不改变 `FOLLOW_TEMPLATE` / `FORCE_DEFAULT` 的解析顺序，不批量重写历史模型值。
- 保存更新时省略 `modelId`，不得因表单默认值覆盖已有值。
- 删除表单对 `useEnabledModels()` 的依赖时，只移除员工表单不再使用的调用，不影响其他页面模型管理。

### 3.3 AI 生成简介

- 描述保持为员工对外简介，允许人工编辑，建议控制在 1-3 句。
- “AI 生成简介”操作依据名称、行业、岗位和已选能力名称及说明生成建议文案；生成结果仅填入编辑框，不自动保存或发布。
- 请求由运营端管理员权限保护，走后端 Sub2API 中转，不在 Web 端持有上游密钥或直连模型供应商。
- AI 生成不阻塞保存流程。失败时保留原文并显示可理解的错误，可继续手动编辑。
- 输出控制在 30-60 个汉字；服务端限制输入、请求时长、输出长度，并对接口限流。

### 3.4 系统提示词辅助填写

- 系统提示词继续保留，因为它在运行时会作为模型指令，直接影响员工行为。
- “AI 生成提示词”操作依据员工名称、行业、岗位及所选能力生成含工作目标、能力说明、工作要求和边界的提示词；生成结果可在原始文本框中查看、编辑。
- 新建和编辑继续使用原始文本框，以保留复杂提示词的直接编辑能力；编辑旧员工时原提示词回显不变，仅在管理员主动点击生成后替换。
- 提示词生成与简介生成共用后端 Sub2API 调用路径；禁止浏览器持有上游密钥或绕过中转。长度控制在 250-600 个汉字，服务端限制输出 token 和文本长度。生成失败不影响保存现有提示词。
- 保存仍遵循现有 DTO 校验及服务端约束。前端不得把缺失提示词静默替换为通用文本。

### 3.5 能力绑定选择器

创建页和编辑页统一改造能力选择区：

- 增加搜索输入，按能力名称、描述、类型实时过滤，忽略大小写并去除首尾空格。
- 提供类型筛选（AGENT、SKILL、RPA、AI_APP），选项以接口返回类型为准；搜索与类型筛选可组合。
- 能力列表放入有边界的滚动区域，建议桌面端最大高度约 480px，窄屏端最大高度约 55vh；滚轮只滚动能力列表，不锁死页面整体滚动。
- 列表顶部持续显示已选数量和至少选择一个能力的约束。过滤后隐藏的已选能力仍然保留，并可通过“仅看已选”筛选找到和取消。
- 搜索无结果时显示空状态；清空搜索和筛选操作可恢复完整列表。
- 保持卡片多选和现有选中样式，不使用原生长下拉框承载大量能力。
- 已选顺序继续决定当前保存时的绑定优先级；新增选中项追加到末尾，取消后再选择追加到末尾。此行为与当前 `selectedCapabilities` 数组提交顺序一致。
- 编辑页加载绑定数据和能力列表的先后顺序不得导致已有选择丢失；数据加载后仅初始化一次，用户开始操作后不被异步响应重置。
- `selectedCapabilities` 必须校验所选 ID 仍有效；搜索/筛选只控制展示，不修改绑定集合。

## 4. 接口与数据兼容

- 不新增数据库迁移。
- 员工 create/update 请求继续使用共享 DTO；`avatar`、`modelId` 等可选字段通过省略表示“不修改/使用后端默认”，不得发送空字符串或客户端占位值。
- 文案生成接口：`POST /admin/employees/copy-draft`，受现有管理员鉴权保护，DTO 使用严格 Zod schema；服务端执行输入长度限制、超时和速率限制。请求不能指定上游 URL、供应商凭据或任意模型。
- 文案生成使用平台当前可用的默认会话模型：优先选择有效的 `SUB2API_DEFAULT_MODEL`；若该值不在已启用且未下架的平台模型中，则按平台排序选第一个可用模型；没有可用会话模型时返回服务不可用，不回落到历史代码常量。该运营端功能没有企业/订阅/会话上下文，不读取员工 `modelId` 或企业覆盖；响应返回实际 `modelId`，页面展示最近一次生成所用模型。
- 生成请求只返回草稿及模型标识，不会自动保存员工资料；AI 输出被视为不可信草稿，管理员检查后手动保存。
- 不调整市场公开字段白名单，不增加公开接口对 `systemPrompt` / `modelId` 的返回。

## 5. 实施顺序

1. 已复用一个能力选择组件覆盖新建/编辑页，支持文本搜索、类型筛选、仅看已选、计数、滚动及空状态。
2. 已移除头像 URL 与模型选择入口；create/update 请求省略相关字段。
3. 已增加基于员工信息和能力的 AI 简介/提示词草稿；旧提示词保留原样回显并可继续编辑。
4. 已增加受管理员鉴权的文案生成接口，使用平台 Sub2API 默认模型，补齐输入输出长度限制、超时和速率保护。
5. 后端 20 项、前端 12 项针对性测试通过；两端类型检查、定向 ESLint 和 `git diff --check` 通过。浏览器视觉验收因当前无运营端登录态未完成。

## 6. 验收标准

### 表单字段

- 新建、编辑员工页面不再出现头像地址或模型选择控件。
- 更新员工其他字段不会清空、更改头像，也不会覆盖既有 `modelId`。
- 新员工使用系统默认头像风格；管理员仍可在头像风格管理页更改默认或单独设置。
- 既有员工的描述、提示词、头像和模型历史数据可以正常读取及运行。

### 文案辅助

- 描述建议可按员工信息生成并编辑；管理员可以不使用建议而手工填写。
- 新建页的 AI 提示词草稿能根据岗位/能力形成具体内容；管理员可修改并保存。
- 编辑旧员工时完整提示词不会被初始化逻辑清空、转换或静默覆盖。
- AI 建议失败时，表单仍能按已有数据手工保存。
- 简介和提示词生成均走平台统一 Sub2API 模型，响应模型标识可见，不受员工或企业模型设置影响。
- 浏览器 bundle 和请求中不包含上游 API key，不存在绕过 Sub2API 的模型调用。

### 能力选择器

- 能按名称、描述和类型搜索；类型过滤与搜索可组合。
- 长列表在限定高度区域内滚动，页面主体仍可正常滚动；键盘可操作搜索、筛选和复选框。
- 过滤不会取消隐藏的已选能力；能仅查看已选项并取消选择。
- 无结果、加载中、无能力、能力加载失败状态均清晰可见。
- 新建和编辑仍要求至少选择一个能力；保存的绑定顺序仍对应优先级。
- 编辑页已有绑定完整回显，异步加载及筛选不会丢失用户选择。

- 运行员工新建/编辑页面相关 Vitest/Testing Library 测试；补充能力选择器组件测试，覆盖搜索、类型筛选、隐藏已选保持、顺序和滚动容器属性。

- 检查后端既有员工 DTO/service 测试，确认字段省略语义不会覆盖头像或模型；若新增文案生成 API，再增加鉴权、长度限制、超时/失败及上游代理测试。
- 不改数据库 schema 时不运行迁移；不得用 mock 编译成功替代实际交互验证。

## 8. 风险与决策点

- `modelId` 当前仍参与 `FOLLOW_TEMPLATE` 策略回退。隐藏模型控件不会使该字段失效；若产品希望所有员工都只使用企业统一模型，须另行评估企业存量策略并设计迁移。
- 新员工头像风格依赖可用素材绑定。未绑定到平台默认风格的员工可能需要在头像管理流程中显示明确的默认/回退状态，不能因此回退到空头像。
- 文案生成质量与岗位、能力元数据质量相关；生成文本必须由管理员检查，不能自动发布或覆盖旧提示词。
- 创建页与编辑页当前存在工作区未提交改动，实施前需逐段核对，保留并兼容这些更改。
