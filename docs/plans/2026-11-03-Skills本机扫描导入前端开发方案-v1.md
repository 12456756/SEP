**目标：** 运营人员在 SEP 网页发现本机各 Agent 的 Skills，预览并选择一个技能，无需手工压缩即可导入，随后创建待平台审核的能力。

**架构：** 保留当前路由和能力表单，在第 2 步增加导入来源页签。本机扫描、预览和打包由用户设备上的助手完成；前端接收选定包后复用现有平台上传和创建接口。首期支持多个候选、单项导入，ZIP 上传保留。

**技术栈：** 现有 Next.js App Router、React、TypeScript、TanStack Query、React Hook Form、共享 Zod schema、Shadcn/Radix、Tailwind、lucide-react、Vitest、Playwright；不新增依赖。

关联依据：[本地 Agent Skills 扫描上传可行性调研](../research/2026-11-03-本地Agent-Skills扫描上传可行性调研.md)。浏览器权限与 Agent 目录官方依据见该文，本文不重复定义扫描目录规范。

## 1. 范围与完成标准

### 1.1 首期交付

1. 平台选择区域继续使用原有交互；Skills 副标题改为 `SKILL.md 标准技能包`。
2. 第 2 步由“上传 SKILL.md 包”改为“导入 Skills”，提供“本机扫描”“ZIP 上传”两个页签，首次默认本机扫描。
3. 本机页提供连接/配对、来源筛选、搜索、作用域筛选、候选单选、正文与文件清单预览、扫描取消和刷新。
4. “导入所选技能”先从助手取 ZIP，再上传到 SEP，返回元数据后填入现有能力信息表单。
5. 保留名称、描述、行业、岗位和“创建并进入平台待审”；不自动创建、审核或绑定员工。
6. 完整处理未连接、权限问题、无结果、部分目录失败、包变化、上传失败、创建失败及请求过期。
7. 桌面列表与预览并排；窄屏分为列表和详情两个可返回的视图。

### 1.2 本期边界

- 仅全局 `ADMIN` 首次创建；企业管理员角色不等同于平台 ADMIN。
- 不新增网页任意路径输入、全盘搜索、目录选择 fallback、批量创建或在线编辑 SKILL.md。
- 不在 Next.js 服务端、Route Handler 或云端 backend 读取用户本机路径；本机接口由浏览器直接访问助手。
- 不改变现有认证、审核、员工绑定、模型配置和执行协议；不增加数据库迁移。
- 助手安装包、扫描引擎与配对服务是配套交付。mock 仅用于开发和自动化测试，不作为可上线的扫描功能。

## 3. 页面设计

### 3.1 桌面信息结构

```text
新建 Agent 能力

1. 选择平台
   Coze / Skills / 其他现有选项

2. 导入 Skills
   [本机扫描] [ZIP 上传]

   扫描助手：已连接                         [断开]
   [搜索技能……] [来源：全部 v] [范围：个人 v] [扫描] [刷新]

   技能列表                               所选技能
   ○ frontend-design    Claude Code       pdf
   ● pdf                共享目录          描述、来源、作用域
   ○ research           OpenCode          本地路径（可展开）
                                          [正文] [文件清单]
                                          预览内容 / 文件及体积
                                          警告或阻断原因
                                          [导入所选技能]

   已导入：pdf.zip / 12 个文件 / 48 KB       [更换技能]

3. 能力信息
   能力名称 / 能力描述 / 行业 / 岗位

[取消] [创建并进入平台待审]
```

### 3.2 布局规则

- 沿用运营后台字体、颜色 token、边框和按钮风格，不把本次变成全页视觉重做。
- 第 2 步作为一个导入工具区域，连接区、工具栏、列表、预览以分隔线组织；不在现有 Card 内嵌套装饰 Card。
- 有效内容宽度 >= 960px 时采用两列：列表 `minmax(260px, 0.9fr)`，预览 `minmax(0, 1.1fr)`；优先按内容容器判断，避免侧栏占宽后仍挤成两列。
- 列表和预览的工作区高度建议 440px，宽屏可增至 560px；使用 `min-height: 0` 和内部滚动，不因描述长度或 hover 导致整体跳动。
- 低于该内容宽度时显示单列列表；选择一项进入详情，顶部“返回列表”，返回保留搜索、滚动位置与选择。底部导入操作不得遮挡预览内容。
- 工具栏可换行；来源/范围用 Select，模式用 Tabs，候选用原生 radio 或现有可访问单选结构；不为单项导入使用 checkbox。
- 扫描、刷新、断开、返回使用现有 lucide 图标；图标按钮有可访问名称和 tooltip。扫描执行中对应按钮显示真实阶段并允许取消。
- 普通名称/描述换行；长路径、文件名、哈希使用 `overflow-wrap:anywhere`。源码局部横向滚动，不使页面产生横向溢出。
- 不使用随 viewport 缩放的字体或负字距；标题、行高、按钮高度采用现有组件规格。新增框体圆角不超过 8px。

### 3.3 连接区域

| 状态 | 显示内容 | 可用操作 |
|---|---|---|
| 初始未连接 | “扫描助手未连接” | 下载助手、连接助手、切换 ZIP |
| 检测中 | “正在连接扫描助手” | 取消 |
| 等待配对 | 配对码输入、配对错误位置 | 配对、取消 |
| 已连接 | 助手版本、连接状态 | 扫描、断开 |
| 协议不兼容 | “扫描助手版本不兼容” | 下载更新、重新连接、ZIP 上传 |
| 请求被浏览器拦截或连接失败 | “无法连接扫描助手”及可确认的原因 | 重试、ZIP 上传 |
| 会话过期 | “连接已过期，请重新配对” | 重新连接 |

首次加载页面不探测 localhost，不触发浏览器权限提示。用户点击“连接助手”后才检测健康状态；不能将一个 fetch 网络错误武断解释为“未安装”，因为也可能是 CORS、权限、端口或策略问题。

下载入口必须来自正式发布配置或现有可信下载页。没有真实下载资产时显示实际安装指引/联系入口，不渲染无效下载按钮或编造安装包地址。具体启动操作可在独立帮助弹窗提供，主工作区不展示实现原理或技术教学。

配对码仅输入一次，不提供记住凭据选项，不自动读取剪贴板；失败后保留输入供修改，成功后清空。

### 3.4 候选列表与筛选

- 默认范围为个人；项目/全部只使用助手已授权的项目 root ID。项目列表为空时显示“尚未配置项目目录”，由助手本机完成配置，网页不输入路径。
- 首期搜索名称和描述；来源筛选是目录来源/兼容来源筛选，不宣称检测到软件已安装。共享目录保留“共享目录”标签。
- 搜索与 Agent 筛选基于已取回摘要本地计算，不因每次输入重新扫描磁盘；改变扫描范围或项目才新建扫描任务。
- 首期已完成清单在前端每页展示 25 条；对排序结果先筛选后分页。扫描仍进行中时不允许导入尚未准备好的条目。
- 缺少 description 可以显示“未提供描述”；解析警告作为提示展示，不额外引入名称必须英文、描述至少 10 字等限制。
- 同一路径按规范化后的根/候选身份去重；仅在助手确认完整内容哈希一致时聚合不同位置。哈希未知时不按名称合并。
- 选中项被筛选隐藏时，详情继续显示，并提示当前已选名称；不能自动选中筛选后的第一项。
- 本地路径默认收起，展开仅在当前浏览器展示；不用于平台查询参数、创建 metadata、埋点或错误日志。
- 没有候选、筛选无匹配、全部目录失败是不同状态。部分目录失败时显示数量和本地诊断入口，其余可用候选继续操作。

### 3.5 预览与导入结果

- 点击候选后向助手请求该项预览；摘要中不夹带全部候选正文和附件内容。
- 预览包括名称/描述/来源/作用域、完整 SKILL.md、最终文件清单、包体积估算和警告。文件清单分页 100 条，不一次渲染 10,000 个节点。
- 默认正文渲染视图，提供源码视图；保留 YAML 与原文，不把前端渲染结果当作上传正文。
- 不渲染原始 HTML，不使用 `dangerouslySetInnerHTML`，不加载外部图片/iframe；图片显示文件名或占位说明，防止预览向外部发送请求。
- 不执行脚本，不发起远程资源补全；相对文件链接仅作路径展示。外部链接只允许明确的 http/https，点击才打开新标签并设置 `noopener noreferrer`；禁用 javascript/file/custom scheme。
- 预览快照必须由助手绑定该候选；阻断项存在时禁用导入，warning 不自动等价于阻断。
- 点击“导入所选技能”后依次显示“正在打包”“正在上传”“已读取技能包”。当前 fetch 上传没有真实字节进度，使用阶段状态和 spinner，不伪造百分比。
- 平台响应后显示文件名、文件数、ZIP 字节大小与可展开完整 SHA-256。服务器兼容性警告按 code/message 去重，保持现有不展示 warning.path 的行为。
- ZIP 页签复用相同的上传结果与失败样式；选择文件后开始上传，保留当前非后缀强拦截行为，最终格式由服务端判定。

## 5. 数据与状态

### 5.1 关键类型

下列是设计契约示意，落地时通过 Zod 推导网络数据类型，不维护两套相互漂移的 interface/schema。

```ts
type ImportSource = 'local' | 'zip';
type ScanScope = 'user' | 'project' | 'all';

type ConnectionState =
  | 'disconnected' | 'connecting' | 'pairing'
  | 'connected' | 'expired' | 'incompatible' | 'error';

type ImportPhase =
  | 'idle' | 'scanning' | 'ready' | 'previewing'
  | 'packaging' | 'uploading' | 'uploaded' | 'error';

type SkillWarning = {
  code: string;
  message: string;
  severity: 'warning' | 'blocking';
};

type CandidateSummary = {
  candidateId: string;
  name: string;
  description: string | null;
  sources: string[];
  scope: 'user' | 'project';
  locations: Array<{ rootId: string; displayPath: string }>;
  treeHash: string | null;
  availability: 'previewable' | 'blocked';
  warnings: SkillWarning[];
};

type SkillPreview = {
  candidateId: string;
  snapshotToken: string;
  expiresAt: string;
  content: string;
  treeHash: string;
  fileCount: number;
  totalUncompressedBytes: number;
  estimatedPackageBytes: number | null;
  files: Array<{ relativePath: string; bytes: number }>;
  warnings: SkillWarning[];
};

type UploadedSkillArtifact = {
  sourceKey: string;
  zipPath: string;
  sha256: string;
  fileCount: number;
  totalSize: number;
  filename: string;
  content: string;
  suggested?: { name: string | null; description: string | null };
  warnings?: Array<{ code: string; message: string }>;
};
```

`sourceKey` 是仅在前端使用的导入身份：本机来自会话/候选/快照，ZIP 来自本次选择的随机 ID。它不能用显示名或路径替代，也不能发往创建接口。`treeHash` 是目录快照哈希，平台 `sha256` 是 ZIP 字节哈希，二者不互换。

### 5.2 状态归属

| 数据 | 放置位置 | 生命周期 |
|---|---|---|
| 配对 token、AbortController、当前操作序号 | hook 内存 ref/闭包 | 断开、退出、身份改变、卸载即清理 |
| roots、扫描进度/清单、单项预览 | TanStack Query，`skill-import` 独立 key 前缀 | 会话私有；禁用持久化、会话结束移除 |
| 来源页签、搜索、来源筛选、页码、单选、窄屏视图 | 组件 state/reducer | 页面内保存；无需引入全局 Zustand slice |
| 上传 mutation 状态 | `useSkillPackageUpload` | 当前单项请求；不保存多份大 Blob |
| 已确认上传元数据 | 表单接收 artifact | 候选/来源改变即失效；创建完成或离开即释放 |
| 名称/描述/行业/岗位 | React Hook Form | 用户编辑期间保留；不复制共享校验规则 |

Query key 包含 `userId`、桥接本地会话 ID、scanId/candidateId；不包含 token、绝对路径或完整正文。不使用 query cache 保存配对 token；配对 mutation 消费凭据后只返回非敏感连接状态。相关 query 设置 `gcTime: 0`，并在退出/断开时显式 cancel/remove；仅设置 gcTime 不能代替清理仍活动的 query。

### 5.3 主要转换与保护

```mermaid
flowchart LR
  A[连接助手] --> B[配对]
  B --> C[扫描]
  C --> D[选择候选]
  D --> E[预览快照]
  E --> F[打包]
  F --> G[上传平台]
  G --> H[已上传]
  H --> I[填写信息并创建]
  I --> J[待平台审核]
```

- connection state、scan query、import phase 与 create mutation 独立；连接失效不能抹掉已完成的平台上传，已上传也不代表能力已创建。
- 所有异步操作捕获当前用户、sourceKey、scanId、candidateId 和递增操作序号。结果返回时逐一核对，任一变化均丢弃；仅 abort 网络请求不足以避免旧 Promise/401 重试结果回写。
- 切换候选、切换来源、开启新扫描时，立即使旧 artifact 无效并通知表单 `null`。保留用户字段；重新选回旧候选也不能自动恢复旧上传结果。
- 打包/上传过程中禁用来源、候选和范围切换，提供取消导入；取消后增加操作序号、释放 Blob、恢复可选状态。创建请求发送后不提供“取消创建”的虚假回滚操作。
- 搜索/筛选仅改变可见项，不改变选中身份或 artifact。切换到新范围必须先取消旧扫描，不能让两个任务的结果混在同一列表。
- 取消扫描可 best-effort 调用助手 DELETE；清理失败不妨碍本地撤销旧结果。页面关闭无法保证 DELETE 送达，助手须通过 TTL 回收资源。
- 切换 Coze、取消返回或刷新页面遵循现有表单离开行为；不额外自动保存正文、token、路径或 Blob。数据未保存提示仅在项目现有惯例允许时复用，不能引入新的全站拦截。

### 5.4 字段预填规则

对名称/描述分别记录 `empty / suggested / user` 来源及所属 sourceKey：

| 情况 | 行为 |
|---|---|
| 初始空字段，平台返回 suggested | 写入推荐内容，不标记为用户手动输入 |
| 用户已输入或显式清空字段 | 保留用户值，按共享 schema 校验；不以建议值覆盖 |
| 换技能后字段仍是旧建议值 | 清除旧建议；新上传成功后以新建议填入 |
| 换技能后字段已被用户编辑 | 保留并提示“将沿用已填写的能力信息”，允许用户自行更改 |
| 新包无 suggested | 空字段保持为空；缺字段时由表单提示补齐 |
| 上传返回 content | 保留该响应原值提交；不重新拼接 YAML、不使用预览 HTML 替代 |

行业/岗位不随候选变化自动清空。创建按钮同时要求共享表单校验通过、当前 sourceKey 对应 artifact 有效、没有导入或创建操作进行中。

若使用 RHF `formState.isValid` 控制按钮，表单需采用 `mode: 'onChange'` 等可在提交前更新有效性的模式，建议预填同时触发校验。不能在默认仅提交校验的配置下，让首次提交按钮因尚未校验而始终禁用。

## 6. 平台接口接入

本节为**现有接口**，浏览器仍通过 `/api` 同源代理访问。

### 6.1 上传

```http
POST /api/admin/capabilities/upload-skill
Authorization: Bearer <现有内存 access token>
Content-Type: multipart/form-data; boundary=<由浏览器生成>
```

FormData 仅追加一个 `file: File`，不手工设 Content-Type，不附加本地路径或扫描清单。助手返回 ZIP Blob 后，以其安全文件名构建 `File`，与用户选择 ZIP 共用 `uploadPackage(file)`。

响应沿用 `zipPath/sha256/fileCount/totalSize/filename/content/suggested/warnings`。`content` 按响应原值处理，它不保证与本地原始 SKILL.md 逐字相同；最终正文以当前平台包解析约定为准。

本机包响应的 ZIP 哈希与上传响应 `sha256` 必须一致；不一致时 artifact 无效，提示重新导入。前端响应解析使用现有共享契约或从已核对字段抽出的公共契约，不误用字段名不同的贡献上传响应替换运营响应。

### 6.2 创建

```http
POST /api/capabilities
Authorization: Bearer <现有内存 access token>
Content-Type: application/json
```

继续使用现有 `SkillForm` DTO 结构：`type: 'skill'`、能力信息、`inputSchema/outputSchema`、包 metadata，以及当前 skillConfig 字段。只从有效 artifact 读取 `zipPath/sha256/fileCount/totalSize/filename/content`，不发送候选 ID、snapshotToken、bridge token 或本地绝对路径。

成功后沿用“创建成功，技能已进入平台待审，审核通过后才会公开”，失效 `capabilities`、`skill-versions` 缓存并导航到 `/admin/skills`。不请求 `/contributions` 创建，也不请求 approve/review。

### 6.3 认证、取消与未知结果

- 平台请求使用 `api-client`，沿用其现有 401 刷新与至多一次重放；功能 hook 不另写刷新逻辑，不改变 refresh 方法或 cookie 行为。
- 当前 `uploadForm` 不接受 signal。为了提供真实“取消上传”，可将其 opts 最小扩展为额外支持可选 `signal`，保留现有 boolean 参数兼容；signal 传入 fetch，重放前检查已取消，重放沿用同一 signal。
- 若平台上传已写入服务器但用户随后取消，前端只撤销引用，不能宣称服务器包已删除；不新增删除包接口。
- 创建 mutation 设置 `retry: false`；按钮防双击。用户切换身份时，旧创建结果不得更新新用户 UI 或触发导航。
- 创建网络错误/超时无法确认是否已写库时，显示“创建结果尚未确认，请先到技能列表核对”。禁用盲目重试；用户主动核对后才允许再次提交。同名查询不是可靠幂等证明，本期不能声称实现 exactly-once。
- 明确收到创建 400/403 等失败响应时保留 artifact 与字段，按错误原因修正/重新登录。页面未刷新且身份仍一致时，不因助手已断开强制重新打包。

## 7. 助手对接契约

本节为**拟新增的 v1 契约**，当前 `sep-skill.mjs` 只有未配对的 `/health/scan/package` 原型。生产前端不静默降级到旧无授权接口。

### 7.1 连接配置与请求规范

- 默认固定 `http://127.0.0.1:3210`；不对端口/私网地址做探测扫描，不从 URL query、Skill 正文或网页输入读取 base URL。
- 若部署需定制端口，仅允许受信部署配置给出经过校验的 loopback 地址；该地址是用户设备地址，不是 Docker backend 地址。
- 所有请求 `credentials: 'omit'`、`cache: 'no-store'`，从独立 bridge client 发出；浏览器自动生成 Origin，前端不手工伪造 Origin/Host。
- `/health` 和 `/pair` 不携带平台凭据；配对后请求带 `X-SEP-Bridge-Token` 和 `X-SEP-Bridge-Protocol: 1`。
- 配对响应 token 仅存在 hook 内存；助手按真实请求 Origin 绑定会话、Host/Origin 白名单、TTL 和取消状态，并允许必要 CORS 预检。
- 助手对允许来源暴露 `Content-Disposition`、`X-SEP-Package-Sha256` 等实际需读取的响应头。其他页面来源无法获得授权数据。

### 7.2 接口一览

| 方法与路径 | 请求 | 响应与语义 |
|---|---|---|
| `GET /v1/health` | 无敏感参数 | `protocolVersion: 1`、`scannerVersion`、`pairingRequired`、capabilities |
| `POST /v1/pair` | `{ code }` | `bridgeToken`、`sessionId`、`expiresAt`；code 一次性使用，错误/限速单独返回 |
| `GET /v1/roots` | 配对 headers | 已在本机授权的 `rootId/label/scope`；候选显示路径只在本机响应出现 |
| `POST /v1/scans` | `{ scope, projectRootIds }` | 202 `{ scanId, status: 'running' }`；root ID 非授权集合则拒绝 |
| `GET /v1/scans/:scanId` | 配对 headers | `status`、`items: CandidateSummary[]`、root diagnostics、过期时间；首期返回当前有界完整摘要集合 |
| `GET /v1/scans/:scanId/candidates/:candidateId/preview` | 配对 headers | `SkillPreview`；仅访问当前会话的当前候选，创建/返回短时快照 |
| `POST /v1/scans/:scanId/package` | `{ candidateId, snapshotToken }` | ZIP 二进制，文件名及 ZIP SHA-256 响应头；确认快照有效与源文件未变化 |
| `DELETE /v1/scans/:scanId` | 配对 headers | 204；停止任务并释放其快照；重复删除可幂等成功 |
| `DELETE /v1/session` | 配对 headers | 204；撤销配对及相关扫描/快照；前端即使调用失败也立即清理本地凭据 |

预览、roots 和撤销 session 是对前期调研草案的细化；助手尚未提供它们时，只能完成 mock UI 阶段，不能宣称支持完整真实扫描。

### 7.3 响应约束与资源限制

- 所有 JSON 在边界通过 Zod 验证。拒绝未知协议主版本、无效 ID/哈希、非法字节数、过期时间、超预算正文/清单；显示受控错误，不把任意助手响应直接作为 HTML。
- capability 至少描述是否支持 `scan`、`preview`、`package`、`cancel`；缺任一首期必要能力显示不兼容，不进入半可用流程。
- 个人/项目 roots 来自助手配置；前端不发送 cwd、home、任意 path，也不向服务器保存 root ID 或 displayPath。
- 候选 `sources` 保留未来扩展字符串，未知来源展示“其他”；不因目录适配新增来源导致整个响应解析失败。
- 首期每会话候选上限建议 1,000 个；截断需明确 `truncated` 与原因，不能宣称全量扫描完毕。上限属于拟定助手协议预算，不是当前已实现配置。
- 完整 `SKILL.md` <= 2 MiB、文件清单 <= 10,000、解压内容 <= 500 MiB、ZIP <= 100 MiB，数值引用共享常量，不复制另一份业务预算。
- JSON preview 包括有界文件清单；浏览器分页渲染，不缓存附件二进制。切换候选立即释放旧 preview 查询与 ZIP 对象引用。
- 预览与打包读取同一 snapshot；原文件变化、快照到期、会话被撤销均拒绝打包。前端不能自动绕过 409 重打包并直接上传，须用户重新查看并确认。
- 服务端 ZIP 完整性与权限校验仍是最终标准；前端检查用于早反馈，不替代后端。

### 7.4 查询策略

- 健康检测只由连接操作触发；连接/配对 mutation 不自动重试，确保不重复消耗配对码或触发权限提示。
- roots 在配对成功后获取；POST scans、打包、上传、创建均 `retry: false`。
- 扫描运行时每 1 秒查询进度，页面后台暂停；恢复焦点后只读取同一任务的状态，不自动启动新扫描。
- 只有 `completed` 且预览有效的候选可导入；`failed/cancelled` 不伪装成空列表。
- 查询 scan 的暂时网络失败保留最后摘要并标记不可导入，停止自动重试，由用户刷新恢复；终态后停止轮询。
- 单项预览只在用户选择后请求；关闭/换项取消旧请求。Blob 不放 React Query 缓存。
- 建议超时：health 3 秒、pair/roots 10 秒、预览/打包 60 秒；扫描整体建议 120 秒。超时均可由受控配置调整，不伪造操作完成。

## 8. 异常处理矩阵

| 场景 | 页面处理 | 后续动作 |
|---|---|---|
| 助手不可达 / 浏览器 fetch 失败 | 连接区显示不可达，不伪称“未安装” | 连接重试或 ZIP 上传 |
| 本地网络权限拒绝、CORS/CSP 等阻断 | 若有明确异常可分类提示；否则统一连接失败 | 给出恢复入口，不要求关闭安全机制 |
| 配对码无效/限速 | 保留配对界面；429 按可读取的 Retry-After 等待 | 用户修改后重试 |
| bridge 401 | 清理 token，停止扫描请求；保留已完成平台 artifact | 重新配对，不触发平台 refresh |
| bridge 403 | 展示来源/范围不允许 | 停止请求，不换不安全接口 |
| 协议版本或响应结构不兼容 | 标记 incompatible | 更新助手或 ZIP 上传 |
| 某项目无权限 / 某目录失败 | 本地显示诊断数量，不向平台日志发送路径 | 其他可用项继续 |
| 候选有 warning | 显示提示，保留导入能力 | 不将未知 warning 全部转为 blocking |
| 候选或快照 404/410 | 清空当前 preview 与 artifact | 重新扫描/预览 |
| 文件变化 409 | 标记“文件已变化，请重新预览” | 新快照后由用户再次确认 |
| ZIP / 内容超预算 413 | 显示限制与实际体积（已知时） | 本机处理后重新导入 |
| 上传平台 401 | 沿用平台客户端刷新一次 | 失败后重新登录；不匿名备用上传 |
| 上传平台 403 | 无有效 artifact，不允许创建 | 提示平台权限；不发第二条旁路请求 |
| 上传校验失败 | 显示平台返回的受控原因 | 保留选择，允许修复后重新预览 |
| 创建明确失败 | 保留包元数据和字段，显示错误 | 修正或重新认证后提交 |
| 创建网络中断/结果未知 | 单独标记 unknown，不显示“确定未创建” | 去技能列表核对；不自动重试 |
| 身份切换 / 退出 / 卸载 | abort、增加操作序号、移除 query、释放 token/Blob | 不将旧响应写入新页面 |

错误文案不得包含 token、私钥、完整 HTTP headers、原始堆栈或未经处理的任意响应正文。路径仅在本地诊断视图展示，不进入 toast 遥测。

| 契约 | v1 / 不兼容版本、能力缺失、字段预算、过期快照、未知 Agent、合法兼容警告 |

| 导入状态 | A 预览晚于 B 返回、A 上传完成前已取消、来源切换、搜索隐藏选择、重新扫描、原文件变化 |
| 预览 | HTML/script 不执行、远程图片不请求、危险协议不可点、中文长路径、10,000 文件分页、warning 不误阻断 |
| 平台上传 | FormData boundary、内存 token、同包哈希、401 单次刷新、上传取消与 refresh 重放竞争、失败后可恢复 |
| 表单 | 空字段预填、手填/清空保留、旧建议清理、正文原值与 metadata、不走贡献/审核接口、双击与创建未知结果 |
| 权限 | 非 ADMIN 不发连接/上传/创建请求；后端拒绝时不尝试旁路；退出后的旧结果不导航 |
| E2E / 视觉 | 桌面/窄屏、键盘、无溢出、各阶段与失败状态、ZIP 回归、真实 HTTPS 到本机链路 |

## 11. 发布与回滚

1. 先准备满足 v1 的本机助手与测试 fixture；前端可先完成 mock 开发，但不以 mock 通过作为上线依据。
2. 确认助手下载地址、允许的正式 Origin、loopback 连接地址与 CSP；部署前核对实际配置，不擅自更改共享代理基础设施。
3. 完成测试环境 ADMIN 的单项导入、待审核结果和 ZIP 回归；记录助手版本、浏览器版本、操作系统和前后端版本。
4. 若已有项目功能开关则复用；无开关时不为本功能新建通用开关系统，可在发布配置中控制入口显示，助手不可用时仍可进入 ZIP 页签。
5. 发布失败可撤回扫描入口或回退本次前端，继续使用 ZIP 上传。已上传的包和创建的待审记录不因前端回滚自动删除或变更审核状态。

本期不开放 `/contributions` 首次创建，不增加服务器扫描服务，不把本机端口代理到公网。
