# Skills 本机扫描导入前端开发方案 v1

> 日期：2026-11-03。状态：SEP Web、后端及部署配置已实施并完成定向验证；真实桌面客户端与 HTTPS 联调待完成。适用入口：`/admin/capabilities/new` 的 Skills 首次创建表单。
>
> 本方案采用 **SEP Web + SEP 客户端内置免登录扫描模式 + 云端短期导入会话**。不新增独立连接器安装包、后台 daemon 或 localhost 服务。客户端扫描能力随 SEP 客户端安装、升级和签名分发；客户端的企业工作模式仍按现有登录规则运行。首期目标平台为 Windows x64、macOS arm64/x64；Linux AppImage 的协议唤起和打包尚未实测，列为后续适配。
>
> SEP 侧主文档为[本机 Skills 扫描导入全栈开发方案](./2026-11-03-SEP本机Skills扫描导入全栈开发方案-v1.md)，包含后端模块、数据、权限、API、上传和部署验收。本文是 Web 详细设计，与[客户端内置 Skills 扫描开发方案](./2026-11-03-SEP客户端内置Skills扫描开发方案-v1.md)配套。实际交付文件与验证证据见[开发验收记录](../progress/2026-11-03-本机Skills扫描导入开发验收记录.md)，不能据此认定客户端已支持真实扫描。

**目标：** 平台 `ADMIN` 在 SEP Web 中点击“扫描本机”，由已安装的 SEP 客户端自动发现本机 Agent Skills，网页展示候选并完成单项导入，随后沿用现有能力创建和平台审核流程。

**用户体验：** 首次安装/升级新版 SEP 客户端并完成一次站点与设备确认；以后网页点击扫描即可唤起客户端。客户端扫描模式不要求登录企业账号，上传和创建始终归属当前 Web `ADMIN`。

**技术栈：** 现有 Next.js App Router、React、TypeScript、TanStack Query、React Hook Form、共享 Zod schema、Shadcn/Radix、Tailwind、lucide-react、Vitest、Playwright；不新增前端依赖。

## 1. 范围与完成标准

### 1.1 首期交付

1. 第 2 步由“上传 SKILL.md 包”改为“导入 Skills”，提供“本机扫描”“ZIP 上传”两个页签，默认本机扫描。
2. 本机页展示客户端状态、扫描范围、来源筛选、搜索、候选单选、正文与文件清单预览、扫描取消和刷新。
3. Web 创建短期 `importSession`，通过 `sep-import://skills/v1` 唤起客户端免登录扫描模式；客户端主动 HTTPS 领取任务并回传候选摘要。
4. 用户在网页选择候选并确认导入；客户端使用会话限定授权打包、上传，Web 取得权威包元数据后填入现有能力信息表单。
5. 保留名称、描述、行业、岗位和“创建并进入平台待审”；不自动审核、发布或绑定员工。
6. ZIP 页签继续可用，作为客户端未安装、不可用或用户已有 ZIP 的后备路径。
7. 处理未安装/未升级、客户端未运行、唤起拒绝、设备未确认、无结果、部分目录失败、包变化、上传失败、创建失败及会话过期。

### 1.2 本期边界

- 仅全局 `ADMIN` 首次创建；企业管理员、普通 `USER`、`CONTRIBUTOR` 不能通过本入口绕过后端权限。
- 不在网页服务端、Next.js Route Handler 或云端扫描用户路径；扫描只在用户电脑上的 SEP 客户端主进程执行。
- 不新增独立连接器下载、后台 daemon、localhost 端口、浏览器 CORS/LNA、bridge token 或网页任意绝对路径输入。
- 不把 Web access/refresh token 放进深链接，不让客户端获得通用 `ADMIN` API token。
- 首期单项创建，不做批量创建、在线编辑 SKILL.md、全盘搜索或静默后台扫描。
- 保留现有业务认证、审核、员工绑定、模型配置和执行协议；新增导入设备授权与云端会话。Web 不直接改数据库，后端使用现有 Redis/Prisma，设备持久化如需新模型按标准迁移流程完成。

### 3.2 连接和客户端状态

| 状态 | 显示内容 | 可用操作 |
|---|---|---|
| 未连接/唤起未确认 | “请打开 SEP 客户端；尚未安装可下载安装” | 扫描本机（唤起）、下载客户端、切换 ZIP |
| 已确认版本过低 | “请升级 SEP 客户端以扫描本机” | 更新客户端、切换 ZIP |
| 等待站点确认 | 显示网页和客户端相同短码 | 两端确认、取消 |
| 已确认/空闲 | 客户端版本、设备名称、上次在线时间 | 扫描、管理设备、切换 ZIP |
| 扫描中 | 阶段、候选数、错误数 | 取消扫描 |
| 离线/不可用 | 受控原因 | 重试、打开客户端、切换 ZIP |
| 会话过期 | “导入会话已过期” | 重新扫描 |

首次页面加载不探测 localhost，不触发浏览器本地网络权限。仅当用户点击“扫描本机”时，Web 创建会话并打开 `sep-import://skills/v1?instanceId=<id>&sessionId=<id>`，由当前设备上的客户端领取该会话；不能按最近在线设备自动派发，避免扫描到另一台电脑。深链接仅定位会话，不能作为上传凭据。若系统询问是否打开 SEP 客户端，用户确认即可。

默认不要求手工输入配对码。首次设备绑定由网页和客户端显示同一短码，用户在两端确认；已绑定设备复用设备密钥。短码输入仅作为唤起失败或异常恢复入口，不保存到浏览器。

网页无法仅凭唤起超时可靠区分“未安装”“未运行”和“拒绝打开”。没有客户端回传证据时统一显示未连接；设备列表显示的是云端已绑定设备状态，不是本机安装检测。自定义协议必须由用户点击触发；若创建 session 的异步请求后浏览器已失去用户激活，则显示“打开 SEP 客户端”按钮，再点击唤起，不能用自动重试绕过系统提示。

### 3.3 候选列表与预览

- 默认扫描个人用户目录下已知 Agent Skills 根；项目范围只使用客户端已经授权的 `rootId`，网页不输入路径。
- 搜索名称和描述；来源筛选显示 Agent/共享来源；同名不同内容保持独立，相同内容由客户端明确哈希后再聚合。
- 每页最多 25 条；扫描未完成时不可导入未准备好的候选。无候选、筛选无匹配、全部目录失败和部分失败分别展示。
- 预览按需请求，包含名称、描述、来源、作用域、完整 `SKILL.md`、文件清单、包体积和警告。文件清单最多分页 100 条。
- 文件页独立于状态轮询限流（120 次/分钟），临时网络、429、408 或 5xx 按 Retry-After 有界重试至多两次；仍失败时显示重试入口，继续读取失败页并保留已取得的文件。授权失效时停止重试。
- 不渲染 HTML，不执行脚本，不加载外部图片/iframe；仅展示相对路径和受限 Markdown。路径不进入 Web 查询参数、创建 metadata、日志或遥测。
- blocking 禁止导入；warning 只提示。客户端快照必须绑定 candidate，文件变化后需要重新预览并再次确认。

### 3.4 响应式规则

- 内容宽度 >= 960px 时列表和预览两列；较窄屏幕先列表后详情，返回时保留筛选、滚动位置和选中项。
- 工作区建议高度 440px，内部滚动，长路径和文件名 `overflow-wrap:anywhere`，不产生页面横向溢出。
- 沿用平台后台 token、边框和按钮规格。扫描、刷新、取消、返回使用现有 lucide 图标并提供 accessible name。

## 5. 状态与数据契约

```ts
type ImportSource = 'client' | 'zip';
type ScanScope = 'user' | 'project' | 'all';
type ConnectionState =
  | 'disconnected' | 'starting' | 'waiting_client' | 'pairing'
  | 'ready' | 'scanning' | 'offline' | 'incompatible' | 'expired';
type ImportPhase =
  | 'idle' | 'creating_session' | 'starting_client' | 'waiting_client'
  | 'pairing' | 'scanning' | 'results' | 'previewing' | 'packaging'
  | 'uploading' | 'uploaded' | 'cancelled' | 'expired' | 'error';

type SkillWarning = {
  code: string;
  message: string;
  severity: 'warning' | 'blocking';
};

type CandidateSummary = {
  candidateId: string;
  revision: number;
  name: string;
  description: string | null;
  sources: string[];
  scope: 'user' | 'project';
  locations: Array<{ rootId: string; rootLabel: string; relativePath: string }>;
  treeHash: string | null;
  availability: 'previewable' | 'blocked';
  warnings: SkillWarning[];
};

type SkillPreview = {
  requestId: string;
  candidateId: string;
  snapshotId: string;
  expiresAt: string;
  content: string;
  treeHash: string;
  fileCount: number;
  totalUncompressedBytes: number;
  estimatedPackageBytes: number | null;
  files: Array<{ relativePath: string; bytes: number }>;
  nextFilesCursor: string | null;
  warnings: SkillWarning[];
};

type UploadedSkillArtifact = {
  sourceKey: string;
  zipPath: string;
  sha256: string;
  fileCount: number;
  totalSize: number;
  filename: string;
  content: string;
  suggested?: { name: string | null; description: string | null };
  warnings?: Array<{ code: string; message: string }>;
};
```

`sourceKey` 仅在前端标识本次会话/候选/快照，不能替代显示名或路径，也不能发往创建接口。`treeHash` 是目录快照哈希，平台 `sha256` 是 ZIP 字节哈希，二者不可互换。

状态保护要求：切换候选、来源、范围、身份或新建会话时立即使旧 artifact 无效；所有异步结果核对 `userId/sessionId/candidateId/operationId` 后才可写回。取消释放快照和 Blob；客户端离线不抹掉已成功上传的 artifact。查询缓存不持久化 token、绝对路径、正文或 ZIP。

上面的 ConnectionState/ImportPhase 是页面内部状态；接口 `status` 严格使用 `waiting-client/pairing/ready/scanning/results/previewing/packaging/uploading/uploaded/cancelled/expired/failed`，通过显式映射处理，不能把内部下划线状态直接传给服务器。候选必须携带 revision；预览请求为 `{ requestId, candidateId, revision }`，响应 requestId 必须匹配当前请求；selection 为 `{ candidateId, snapshotId, operationId }`。files 始终是数组，后续页为 `{ snapshotId, files, nextFilesCursor }`；完整预览及文件页在后端就绪后才可导入。

```mermaid
flowchart LR
  A[Web 创建导入会话] --> B[sep-import 深链接]
  B --> C[客户端免登录领取任务]
  C --> D[扫描并回传候选]
  D --> E[Web 选择和预览]
  E --> F[Web 确认候选]
  F --> G[客户端限定上传]
  G --> H[Web 获取包元数据]
  H --> I[填写能力信息]
  I --> J[POST /capabilities 待审]
```

## 6. 云端接口契约

以下接口已在 SEP 侧实现，统一使用 `/api/skill-import` 前缀；运行时契约以 `backend/src/shared/skill-import-schema.ts` 为准，真实安装包联调仍待完成。

### 6.1 Web 接口（JWT + ADMIN）

| 方法 | 路径 | 作用 |
|---|---|---|
| `GET` | `/skill-import/config` | 当前 ADMIN + 活跃 WEB sid 读取开关、实例 ID、协议版本和最低客户端版本；功能关闭时仍可读取 |
| `POST` | `/skill-import/sessions` | `{requestId,protocolVersion:1,scope:'user'|'project'|'all'}`，默认 user；同 requestId 幂等创建 |
| `GET` | `/skill-import/sessions/:sessionId` | 查询客户端状态、候选摘要、进度和诊断 |
| `POST` | `/skill-import/sessions/:sessionId/confirm-device` | Web 侧确认设备；需和客户端本地 consent 一起成立 |
| `POST` | `/skill-import/sessions/:sessionId/preview` | `{requestId,candidateId,revision}`；请求候选预览，防止快速切换时旧结果覆盖 |
| `POST` | `/skill-import/sessions/:sessionId/selection` | 确认候选/快照，产生不含凭据的限定打包命令；客户端打包后自行申请 upload grant |
| `DELETE` | `/skill-import/sessions/:sessionId` | 非终态取消；uploaded 后仅关闭授权，保留 uploaded 历史 |
| `GET` | `/skill-import/devices` | 查询当前 ADMIN 未撤销设备；`limit/cursor` 分页，响应 `{items,nextCursor}`，Web 默认每页 25 条 |
| `DELETE` | `/skill-import/devices/:deviceId` | 撤销设备绑定 |

### 6.2 客户端限定接口

客户端通过设备密钥和短期 session proof 访问，不使用通用 Web JWT：

| 方法 | 路径 | 作用 |
|---|---|---|
| `POST` | `/skill-import/connector/pairings` | 首次提交设备公钥和会话定位信息 |
| `POST` | `/skill-import/connector/challenges` | 已有设备密钥领取挑战 |
| `POST` | `/skill-import/connector/grants` | 提交挑战签名和本地 consent，换取短期 session grant |
| `GET` | `/skill-import/connector/sessions/:sessionId/commands?cursor=` | 领取 Web 发出的扫描、预览和打包命令 |
| `POST` | `/skill-import/connector/sessions/:sessionId/events` | 回传状态、候选、预览和诊断事件 |
| `GET` | `/skill-import/connector/sessions/:sessionId/operations/:operationId` | 客户端专用上传结果查询；不复用 Web JWT API |
| `POST` | `/skill-import/connector/sessions/:sessionId/operations/:operationId/upload-grant` | ZIP 完成后凭 session grant 换发本 operation 的受限上传授权 |
| `POST` | `/skill-import/connector/sessions/:sessionId/package` | 使用受限 upload grant 上传选定 ZIP，允许同内容幂等重试 |
| `DELETE` | `/skill-import/connector/sessions/:sessionId` | 客户端释放会话、快照和本地任务 |
| `POST` | `/skill-import/connector/devices/:deviceId/revoke` | 客户端用 device-revoke 挑战签名撤销绑定 |

实际包接收必须复用 `SkillPackageService`、`PackageSecurityService` 和现有包预算，但不放开 `POST /admin/capabilities/upload-skill` 的 ADMIN guard。上传结果返回现有字段 `zipPath/sha256/fileCount/totalSize/filename/content/suggested/warnings`；Web 再调用现有 `POST /capabilities`。

### 6.3 时限与轮询

- 等待客户端领取或首次确认：5 分钟。
- 会话空闲：10 分钟；任务绝对上限：30 分钟；心跳/轮询/授权续期不延长空闲时间，实际新增进度或用户操作可更新空闲时间。
- session grant 最长 10 分钟，客户端提前 60 秒挑战续期。upload grant 在 ZIP 完成后申请，最长 5 分钟且不超过任务剩余时间；上传重试复用同一 operationId/snapshotId/ZIP 哈希与大小。先查询客户端 operation API，processing 时等待，仅 retryable 才重传。grant 不返回 Web，也不进入命令队列，只通过签发 API 返回客户端主进程。
- Web 初始轮询间隔 2 秒；无变化或暂时失败时退避，最大 10 秒；终态停止。
- 预览建议 60 秒超时；包上传沿用现有 100 MiB ZIP、500 MiB 解压内容、10,000 条目、`SKILL.md` 2 MiB 预算。
- 候选摘要和文件清单分页响应最多 1 MiB；包含入口正文或上传结果 `content` 的响应最多 16 MiB（入口原文仍最多 2 MiB，额外空间容纳 JSON 转义和元数据）。不能把多个完整技能正文累积进轮询响应；限制在两端共享契约统一。
- 接口需要取消、过期和幂等语义；超时结果未知时 Web 不自动重复创建能力。

状态与结果读取细节以[全栈方案的 Web API](./2026-11-03-SEP本机Skills扫描导入全栈开发方案-v1.md#71-web-api)为准：默认 `view=status` 只读轻量状态，`view=candidates/preview/files/operation` 分别读取分页候选、单份正文、文件页和操作结果。使用 `uploaded + artifactReady` 后按需取 operation artifact，不能在每次状态轮询中重复传正文。新接口由后端同时验证当前 ADMIN、有效 WEB sid、发起浏览器会话归属及设备撤销状态；客户端提交 uploaded 事件不能产生权威 artifact。

初次授权成功时后端恰好入队一次 scan。网页“刷新扫描”取消旧 session 后重建并再次明确唤起，避免 UI 调用未定义的 rescan API。preview 60 秒超时、CANDIDATE_CHANGED 或 SNAPSHOT_EXPIRED 失效当前预览并回 results，可重新选择；不自动把整个会话设为 failed。前端收到错误的旧 requestId 响应直接忽略。

## 7. 表单接入和上传

现有 `SkillForm` 继续负责名称、描述、行业、岗位、`skillConfig` 和创建 mutation。导入工作区只产生 `UploadedSkillArtifact`，不组装创建 DTO。

### 7.1 客户端导入

1. Web 创建 session，打开 `sep-import://skills/v1?instanceId=...&sessionId=...`。
2. 首次客户端通过 pairings/challenges/grants 完成设备证明和本地 consent，Web 核对短码并确认；grants 的 202 pending 由客户端轮询。同站点/用户/系统用户/范围已绑定时复用确认，但本次深链接及密钥证明仍必需。
3. 客户端领取命令、扫描并回传候选摘要；Web 展示列表。
4. 用户选择候选并按需预览；Web 发送 selection，确认 candidate 和快照。
5. 客户端在本机创建一致快照、打 ZIP，再为本 operation 申请 upload grant 并调用限定上传接口。
6. Web 轮询 session 获得权威 artifact，校验响应 schema、SHA-256 字段格式和体积/条目预算后填入表单。浏览器没有 ZIP 字节，不重算包哈希；实际 SHA-256 和包结构由服务端校验。

浏览器不接收任意本机路径，不直接读取客户端文件或设备密钥。客户端上传成功不等于能力创建成功或审核通过。

### 7.2 ZIP 后备

ZIP 页签沿用现有 `uploadForm('/admin/capabilities/upload-skill')` 和响应字段。两种来源共用 artifact 展示、建议值、警告和 `POST /capabilities`；切换来源立即使旧 artifact 失效。

### 7.3 认证、取消和未知结果

- Web 接口沿用现有内存 access token 和一次 401 刷新/重放；客户端接口不触发 Web refresh。
- 创建 mutation `retry: false`，按钮防双击。创建网络错误且结果未知时提示用户到技能列表核对，不盲目重复提交。
- 退出、身份切换或页面离开时 abort Web 请求、取消 session、清理 query 和 Blob；同时撤销当前导入 grant。设备凭据与桌面工作模式 token 完全分开；服务端通过 TTL 回收未送达的取消请求。
- 不在 toast、URL、日志或埋点输出 token、绝对路径、原始堆栈或未经处理的客户端响应。

## 8. 异常处理

| 场景 | 页面处理 |
|---|---|
| 客户端未安装/版本过低 | 展示正式客户端下载/更新入口；保留 ZIP 页签 |
| 客户端未运行 | 点击“扫描本机”重新唤起；失败时显示打开客户端和 ZIP 入口 |
| 外部协议被拒绝 | 保留 session，显示重试，不要求用户找目录 |
| 首次设备未确认 | 展示两端短码和确认状态；5 分钟过期后重新创建 |
| 设备离线/协议不兼容 | 停止轮询或退避，提示升级/打开客户端 |
| 部分根目录失败 | 显示失败数量和受控诊断，其余候选继续可用 |
| 候选/快照过期或文件变化 | 清空预览和 artifact，回 results 重新预览确认；需要刷新发现列表时取消旧会话再新建 |
| blocking warning | 禁用导入；warning 仅提示 |
| 上传 401/403/413 | 按受控平台错误处理，不绕过权限或改走贡献接口 |
| 创建明确失败 | 保留 artifact 和字段，允许修正后重新提交 |
| 创建结果未知 | 标记 unknown，引导到技能列表核对，不自动重试 |

已经成功取回并交付表单的 artifact 在扫描会话自然到期后保留，允许继续填写能力信息并创建；仅会话到期前尚未取回结果的任务需要重新导入。主动取消、身份变更、切换来源/候选及撤销等明确失效动作仍清空结果。
