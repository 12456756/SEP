# 本机 Skills 扫描导入 P0/P1 实施计划

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 修复本机 Skills 导入的客户端唤起和重复配对问题，提供可靠状态反馈、Agent 来源筛选及 Skills 多选逐个导入/创建。

**Architecture:** Web 在创建导入会话成功后立即尝试跳转受校验的 `sep-import://` 深链接，同时保留手动重试按钮。客户端首次创建的临时 pairing 在服务端发现已记住设备时被原地绑定到该设备，沿用同一个 `pairingId` 和配对码，避免生成第二条配对记录；会话进入 active pairing 后，服务端只向 Web 返回当前有效 pairing。候选可跨页多选；受当前后端单会话单操作契约约束，所选 Skill 逐个预览和上传，每项形成独立 artifact、名称/描述和创建操作，队列状态可恢复，不合并成一个包。

**Tech Stack:** Next.js/React、TanStack Query、NestJS、Redis 会话存储、Electron、TypeScript、Vitest/Jest。

### Task 2: 服务端复用临时 pairing

**Files:**
- Modify: `backend/src/modules/skill-import/skill-import.service.ts`
- Test: `backend/src/modules/skill-import/skill-import.http.spec.ts`

**Steps:**
1. `createChallenge(deviceId)` 查找本会话唯一未绑定、未网页确认的临时 pairing。
2. 找到时原地替换 public key、fingerprint、设备信息、设备授权范围和 challenge，并使旧 challenge 失效。
3. 保留原 pairingId 和配对码，使客户端的 `current.pairingId` 与服务端 grant 返回值一致。
4. 没有唯一临时 pairing 时才创建独立 pairing，并保留现有并发和会话上限保护。
5. 增加首次记住设备、再次扫描和多临时 pairing 的回归测试。
