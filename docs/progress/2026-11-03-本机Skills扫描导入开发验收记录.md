# 本机 Skills 扫描导入开发验收记录

日期：2026-11-03。对应需求：[SEP 本机 Skills 扫描导入全栈开发方案 v1](../plans/2026-11-03-SEP本机Skills扫描导入全栈开发方案-v1.md)。

本轮完成 SEP 后端、Web、设备迁移和部署配置。默认 `SKILL_IMPORT_ENABLED=false`；没有发布生产，也没有将桌面客户端安装包、真实本机扫描或三端 HTTPS 联调标记为通过。桌面实现仍按[客户端方案](../plans/2026-11-03-SEP客户端内置Skills扫描开发方案-v1.md)单独交付。

## 1. 已实施行为

Web ADMIN 在 `/admin/capabilities/new` 选择 Skills，读取实例配置后创建云端短期会话。用户点击“打开 SEP 客户端”通过 `sep-import://skills/v1?instanceId=...&sessionId=...` 定位当前任务；链接只包含定位字段，浏览器不获得本机文件访问权。

桌面模块使用 Ed25519 挑战证明和本机 consent，首次必须同时完成 Web 短码/指纹确认。服务端签发限本会话 grant；客户端主动 HTTPS 领取命令、回传摘要、按需预览与文件页。网页选择快照后，客户端完成确定 ZIP，再申请绑定 operation、SHA-256 和大小的短期 upload grant。不会向客户端发放 ADMIN JWT。

上传入口先验证 grant、当前用户权限、原始活跃 WEB sid、设备撤销和并发准入，再解析 multipart。上传后复用实际 ZIP 权威校验、内容寻址存储和静态检查，Web 获取权威 artifact 预填原表单，仍通过现有 `POST /capabilities` 创建待平台审核记录。上传成功不等于发布。

服务端状态使用共享 Redis，包括会话、命令/事件幂等、nonce、token hash、分布式锁、上传准入和 TTL。依赖不可用时返回受控错误，不回退至进程内状态。角色撤销、退出登录、设备撤销、取消或上传中断均有针对性覆盖。

Web 提供范围选择、明确唤起、配对确认、候选搜索/来源筛选/分页、纯文本正文预览、完整文件清单、operation 查询、取消/重扫、设备分页撤销及 ZIP 后备。身份变化与异步旧回调不能将旧导入写入新会话；创建结果未知时不自动重复创建。

## 3. 对接契约与配置

所有接口相对 `/api`，协议版本为 `1`。运行时字段和允许事件以共享 schema 为准，不复制宽松 DTO。Web 使用业务 JWT 和活跃 WEB sid；客户端的 session/upload grant 不是业务 JWT，Swagger 分别声明。

在原设计 18 条接口基础上新增 `GET /skill-import/config`，共 19 条方法/路径。该接口也需要当前 ADMIN 与活跃 WEB sid，返回 `enabled/instanceId/protocolVersion/minClientVersion`；关闭时仍可读取。Web 页面挂载读取配置，关闭或读取失败时禁用扫描并提示 ZIP，开始前再读取一次配置。此接口不能代替桌面端受信实例白名单。

`GET /skill-import/devices?limit=25&cursor=...` 返回 `{items,nextCursor}`，默认 25、最多 100 条。稳定按创建时间与 ID 分页，仅返回本人当前实例未撤销设备；游标不能跨用户/实例使用。撤销边界设备后仍能继续翻页，旧设备不会被固定 100 条截断。

`POST connector/.../package` 只接收一个名为 `file` 的 ZIP，不接收额外 multipart 文本字段；operation/snapshot/hash/大小已经在申请 upload grant 时绑定。两类 grant 原文只在签发响应中返回，不进入 Web、深链接或命令队列。

签名规范沿用主方案：SPKI DER Ed25519 公钥、无填充 base64url、小写 SHA-256、固定有序 JSON 数组、ISO UTC 毫秒时间。有效证明等待 Web 确认返回 202，不消费挑战；成功返回 200 并一次消费。响应丢失用新挑战恢复，不重复 scan。撤销的旧公钥不得自动恢复绑定，重新配对需新密钥。

| 环境变量 | 默认 / 要求 |
|---|---|
| `SKILL_IMPORT_ENABLED` | `false`；仅接受 true/false |
| `SKILL_IMPORT_INSTANCE_ID` | 启用时必须设置稳定的 1–128 位字母、数字、下划线或连字符；与客户端受信配置一致 |
| `SKILL_IMPORT_MIN_CLIENT_VERSION` | `1.0.0`；正式 `x.y.z`。该默认值是协议门槛占位，不代表已发布该客户端 |
| `SKILL_IMPORT_UPLOAD_CONCURRENCY` | `1`；1–16，所有副本共享准入槽，上调前需做内存/并发验收 |

反向代理将 `/api/skill-import` 直接转发后端，避免经过 Next 缓冲。只有精确 package POST 放行 101 MiB HTTP body，events POST 为 16 MiB，其余导入路径为 2 MiB；ZIP 文件本身仍由应用限制为 100 MiB。导入代理超时 300 秒。应用继续按事件类型限制摘要/正文及累计预算，不能仅靠代理上限。

## 5. 部署与上线顺序

1. 保持开关关闭。备份并核对目标数据库，按现有发布流程执行 `prisma migrate deploy`；本轮没有对现有业务库执行迁移。
2. 配置固定 instanceId、真正包含扫描模块的最低客户端版本、Redis 和包存储。所有副本必须共享 Redis 和同一个内容寻址包目录/现有支持存储；不能依赖粘性路由掩盖本地文件不共享。
3. 发布后端与 Web 的默认关闭版本，同时应用所选环境的 Caddy 入口规则和 Compose 环境变量。按现有 `TRUSTED_PROXY_CIDRS` 设置明确代理范围，保证解析后的 IP 限流可信。
4. 在同一个 SEP 客户端中实现并发布签名扫描版本，注册系统协议、受信 instanceId/HTTPS endpoint，核对共享 schema 与密码学 fixture。更新官网版本号本身不代表扫描功能已可用。
5. 通过主方案 J01–J14 后，小范围启用开关。确认 WEB A/客户端业务 B 归属 A、首次及复用授权、取消/退出/撤销、上传结果丢失、待审创建和 ZIP 回退。
6. 回滚优先设回 `false` 并重新发布配置，客户端停止失效任务，保留原 ZIP 路径、已上传内容和已创建待审记录；不删除用户本机文件或立刻回滚设备表。
