最新接口交接范围见 [给算力平台的交接文档](./sep-compute-platform-handoff-2026-11-20.md)。本文保留早期 register/prepare/dispatch 等细化提案作评审参考，不作为本轮必须新增接口清单；与最新交接稿不同时，以交接稿为准。

先看业务流程：[扣费方案简明版](./SEP与算力平台扣费方案-简明版-2026-11-20.md)。本文用于技术人员评审接口和账务细节。

日期：2026-11-20。状态：技术评审稿，业务原则已按本次讨论确定；新增接口、字段和状态尚未实现，不能作为当前线上接口调用。

本次评审修订：对话保留“开始检查余额、执行后后台结算”，不增加请求前免费额度/付费资金预占，不强制执行前报价；不新增独立只读价格目录接口。美元转人民币由算力平台完成，双方集成接口以人民币金额结算和对账，SEP 不换汇、不建美元映射账本。以下媒体预占规定只适用于图片、视频，不能套用到对话。

交付对象：SEP 后端、算力平台后端、联调与运维人员。配套金额示例见同目录 `sep-compute-settlement-examples-v1.json`，只读校验命令为 `node docs/development/sep-compute-settlement-verify-v1.mjs`。

## 1. 已确定的业务边界

1. 企业在 SEP 注册后，在算力平台建立独立企业账号；对话、图片、视频各有一个用途受限 Key，三个 Key 共用该账号的一份付费余额。
2. 所有模型单价、倍率、规格价格、报价及实际使用费用均由算力平台管理和计算。SEP 只读取展示，不提供改价入口，不保留用于正式结算的本地价格兜底。
3. SEP 管理免费额度及资金来源。免费额度覆盖的部分只消耗免费权益，不扣双方付费余额；超出免费额度的部分才对应扣减双方付费余额。
4. 钱包划入算力、算力划回钱包，需要与算力平台账号对应增减。免费权益不能退回钱包。
5. 请求可以并发、对话可以流式、视频可以异步。不能为了账务一致将所有模型执行全局串行化。
6. 本协议保证持久化决定、幂等确认、最终账务一致，不声称两个独立数据库在同一时刻提交。已经预占或已扣待同步的资金不可重复使用或退回；对话没有请求前预占，不能据此声称其执行期间资金已经锁定。
7. 费用计算与付费扣款是两个阶段。算力平台先确定实际费用，再按 SEP 确认的免费/付费分配完成扣款；企业集成账号不得继续走原有自动全额扣款路径。
8. 对话采用 `chat_postpaid`：检查余额、登记请求、执行、查询实际费用、后台扣款，不增加执行前资金预占或预算报价。图片/视频采用 `media_reserved`，保留已有报价及预占机制。禁止通过其他字段或远端冻结变相要求对话预占。
9. 算力平台负责美元成本转人民币、汇率规则和换算精度，返回可用于结算的人民币报价、实际费用、账号余额及流水。SEP 只按返回金额记人民币账，不再乘汇率。

## 3. 权威数据、编号与存储

| 数据 | 权威方 | 另一方保存内容 |
|---|---|---|
| 模型价格、报价、最终使用费用 | 算力平台 | 原文、版本、摘要及展示缓存 |
| 企业权限、成员额度、免费赠送来源与资金归属 | SEP | 算力平台保存授权摘要，不自行发放 SEP 免费权益 |
| 执行是否受理、是否可能执行、最终用量 | 算力平台 | SEP 保存状态快照并主动查询 |
| 免费/付费分配及最终结算决定 | SEP | 对话核对实际扣款决定；媒体额外校验原预占上限 |
| 算力账号的人民币结算余额、冻结额及人民币流水 | 算力平台 | SEP 保存返回的人民币金额、状态及远端流水编号，不维护美元映射账本 |
| 美元成本、汇率、美元转人民币及换算余差 | 算力平台 | SEP 可保存返回的版本作审计，不参与换算或倒推美元余额 |
| SEP 钱包、人民币资金来源账本 | SEP | 算力平台保存关联编号及对应人民币结算金额 |

所有资源按 `(integration_id, enterprise_id, business_id)` 隔离；不能仅凭可猜测的远端用户 ID 查询。

| 字段 | 规则 |
|---|---|
| `enterprise_id` | SEP 企业的不可变 ID，跨平台绑定主键，不用邮箱充当企业唯一键 |
| `execution_id` | SEP 发送前生成，标识一次模型执行；长度 1..128，字符 `[A-Za-z0-9_-]` |
| `quote_id` / `price_version` | 算力平台生成；媒体报价绑定企业、用途、模型和规格，对话不要求 quote_id，价格版本随实际费用返回 |
| `bill_id` / `bill_version` | 算力平台生成，最终费用单不可变；v1 版本从 1 开始 |
| `settlement_id` / `decision_hash` | SEP 保存结算决定时生成，绑定执行单、费用单、资金拆分；不可覆盖 |
| `transfer_id` | SEP 生成，标识一次跨平台增减余额，不用管理员请求追踪编号代替 |
| `credential_id` / `credential_version` | 算力平台生成，绑定用途及账号，用于轮换后查询旧任务 |
| `compute_request_id` / `provider_request_id` / `task_id` | 算力平台关联编号、供应商编号、异步任务编号，允许后两项为空 |

执行编号、结算编号、远端请求编号不是一回事。不得使用 Chat Completion 正文的 `id` 或 `X-Request-ID` 代替幂等主键。

双方至少保存：执行单、预占明细、不可变费用单、结算决定/回执、划转单、追加账务流水、可靠投递事件。请求正文及文件可按隐私策略较早清理，不能连带删除账务编号和幂等墓碑；v1 账务及幂等记录至少保留 365 天，正式保留周期在上线前确认。

## 4. 人民币结算、精度与守恒

### 4.1 统一数据类型

- SEP 与算力平台的集成接口统一 `currency=CNY`。报价、实际费用、免费金额、付费金额、充值退回、余额及冻结额均为人民币，固定 6 位小数字符串。
- 禁止浮点 JSON 金额、科学计数法、NaN、Infinity。SEP 使用十进制定点运算完成人民币拆分和记账，不乘汇率、不倒推美元、不再对已返回金额二次舍入。
- 算力平台内部可继续按美元保存成本或记账；内部模型和币种是否调整由算力平台实施方决定，本协议不要求 SEP 维护对应美元账本。
- 数量、Token、秒数使用非负整数；时间使用带 `Z` 的 UTC 时间。金额上限由双方 schema 与数据库容量共同限制，不能静默截断。

### 4.2 美元转人民币的责任

算力平台负责适用汇率、版本、生效时点、舍入及小额余差归集，直接返回可入账的人民币金额。SEP 可保留费用单中算力平台返回的价格/换算版本用于审计，但不要求请求携带 SEP 决定的汇率或美元金额。

算力平台原有“美元余额乘当前汇率”的人民币展示值，不能直接当作本协议的可结算余额。集成账号的人民币余额必须能按人民币充值、实际付费消费、退回逐笔核对，不能因为展示汇率改变就让企业已充值的人民币权益改变。

对话在受理时记录适用价格与换算规则；媒体使用报价绑定的规则。原单已确认的人民币金额不可随之后改价或改汇率重算。具体汇率由算力平台管理，本文不指定 7.2 或 7.15 为上线值。

### 4.3 人民币结算拆分

`G=gross_cny` 为算力平台确认的人民币实际费用。媒体预占 `Fmax=max_free_cny` 和 `Pmax=max_paid_cny`，均使用其人民币报价；公式只适用于 `media_reserved`：

```text
F = min(G, Fmax)
P = G - F
0 <= F <= Fmax
0 <= P <= Pmax
gross_cny = free_cny + paid_cny
```

SEP 按实际权益决定谁承担费用，不重新计算模型价格。媒体开始后新增免费额度不追溯替换原预占分配，未使用预占分别释放。双方直接核对人民币拆分，不进行免费/付费美元分摊或汇率往返换算。

对话不提前锁定权益；后台获得人民币实际费用后，在同一事务内检查当前免费余额、成员权限与付费资金，扣减并保存账单及待同步事件。同一账户的结算使用行锁或版本条件，不能复用发送前免费余额快照。资金口径为：

```text
gross_cny = free_cny + collected_paid_cny + unpaid_cny
```

余额不足时沿用当前欠费记录，未付金额不算已扣款，也不能让算力平台先扣 SEP 尚未收取的部分。收齐资金、拆分持久化后才提交完整结算；待收齐的本地已扣金额单独记录，不能重复消费或盲目退款。欠费补收入口在冻结前与现有产品流程对齐。

对话没有请求前预占，并发执行或转出后仍可能不足结清，需进入欠费/待对账；不能承诺余额只够一次就只执行一次。

### 4.4 两边人民币余额对账

三个 Key 共用一个账号资金池。SEP 保存人民币资金来源账、远端人民币结算回执及流水编号，不建立美元映射账本。

```text
已确认付费人民币总余额 = 已确认转入 CNY - 已确认转出 CNY - 已结算付费 CNY
可用人民币余额 = 总余额 - 媒体消费预占 CNY - 转出预占 CNY
```

免费权益不计入付费资金池，企业整个钱包也不等于该资金池。对账按同一远端流水水位核对人民币可用额、预占额、消费及划转；对话本地已扣但远端未确认、划转未收尾等差额明确列为在途，不能重复当余额使用。

算力平台负责内部换算余差的账务处理和审计，不能把内部余差作为 SEP 再次扣款依据。小额累计和全额退出需要可重放测试；免费权益不折现，退款不得超过原人民币现金权益的未消费部分。

## 5. 服务认证与凭证交付

### 5.1 控制接口认证

新增接口基路径：`/api/v1/integrations/sep`。全部由算力平台提供、SEP 服务端调用；v1 使用主动查询，不要求新增算力平台主动回调 SEP 的公网接口。

必须 HTTPS。控制接口使用独立集成身份，不能使用企业模型 Key 取得任意开户、改余额或免费授权权限。推荐实现以下 HMAC-SHA256 认证，密钥由部署系统配置，不进入业务数据库明文、文档示例或客户端：

```text
X-SEP-Integration-ID: 已登记的集成身份
X-SEP-Key-ID: 服务认证密钥版本
X-SEP-Timestamp: UTC Unix 秒
X-SEP-Nonce: 每个 HTTP 尝试新生成的随机值
X-SEP-Signature: lowercase_hex(HMAC_SHA256(secret, canonical_request))

canonical_request = uppercase(method) + "\n" + raw_request_target + "\n"
                  + integration_id + "\n" + key_id + "\n"
                  + timestamp + "\n" + nonce + "\n"
                  + lowercase_hex(SHA256(raw_body_bytes))
```

`raw_request_target` 包含完整路径及原始查询串，代理不得重写签名目标；空正文按空字节计算。v1 控制资源 ID 禁止路径分隔符；列表查询只允许明确的筛选字段及游标。

时间偏差最多 300 秒；nonce 按集成身份去重，保存至少 600 秒。重试时使用新时间/nonce/签名及原业务幂等键，不能因重复 nonce 重新执行一次业务。

### 5.2 Key 的加密交付

三个 Key 的交付采用标准 JWE 紧凑格式，算法限定 `RSA-OAEP-256` + `A256GCM`；只使用经审查的现有实现，不自制加密算法。SEP 提前登记独立公钥及 `encryption_key_id`，私钥只放部署密钥系统。

密文受保护 Header 绑定 `kid`；解密后的对象必须包含并核对 `integration_id/enterprise_id/compute_account_id/credential_id/credential_version/kind/api_key/issued_at`。服务认证密钥与加密密钥不得复用。

控制响应只返回凭证密文和遮罩信息。SEP 解密后再按本地密钥加密落库，不回传客户端、不记入运行日志。网络超时重试开户只能返回同一批凭证的可恢复密文，不能悄悄再次生成不同 Key。

Key 轮换用独立操作编号。旧 Key 不能执行新任务；原任务查询/下载由新同账号凭证或受限旧版本读取凭证完成，不能因为轮换丢失在途视频账单。

## 6. 接口目录

以下为拟定的集成能力；明确复用的媒体报价不是新增独立服务，其余路径尚未实现。控制接口 JSON 顶层包含 `contract_version: 1`；成功资源响应直接返回对象，不混用多种成功包装。修改操作均要求 `Idempotency-Key`，与对象内业务 ID 校验一致。

| 编号 | 方法和相对路径 | 核心输入 | 返回及作用 |
|---|---|---|---|
| C01 | `POST /accounts` | `enterprise_id, registration_ref, company_name, admin_email, encryption_key_id` | 账号映射、`billing_mode=sep_settlement_v1`、三类凭证密文；首次 201，重复同参 200 |
| C02 | `GET /accounts/{enterprise_id}` | 已签名身份 | 开户状态、账号 ID、凭证用途/版本；不返回 Key 明文 |
| C03 | `POST /accounts/{enterprise_id}/credentials/{kind}/rotate` | `rotation_id, expected_version, encryption_key_id` | 新凭证版本及密文，处理旧任务读取策略 |
| C05 | `POST /inputs` | 企业身份、文件流、SHA256、MIME、大小 | 绑定企业的不可变 `input_ref`，用于媒体报价；不执行、不扣费 |
| C06 | 媒体报价，优先复用 `/v1/sub2api/images/pricing`、`/v1/sub2api/videos/pricing`，集成包装路径暂记 `POST /quotes` | 仅图片/视频的企业、用途、凭证、模型规格及输入引用 | 报价和版本，用于已有媒体预占；不用于对话，不新增独立价格目录 |
| C07 | `POST /executions/{execution_id}/prepare` | 仅媒体：`quote_id, request_ref, free_hold_ref, currency=CNY, max_free_cny, max_paid_cny, funding_hash` | 创建人民币媒体预占记录并返回执行票据 |
| C07A | `POST /executions/{execution_id}/register` | 仅对话：企业、用途、凭证版本、原始模型请求、`settlement_mode=chat_postpaid` | 登记执行及请求快照、返回执行票据；不报价、不冻结免费额度或资金 |
| C08 | `GET /executions/{execution_id}` | 集成身份、资源权限 | 执行、派发、费用及结算状态，包含可用的请求/任务编号 |
| C09 | `GET /executions/{execution_id}/bill` | 集成身份、资源权限 | `pending` 或不可变 `final` 费用单；未完成不能用 0 代替 |
| C10 | `POST /executions/{execution_id}/commit` | 费用单版本、结算决定、免费/付费拆分及结算模式 | 按 SEP 已确认付费部分扣款、记录免费用量；仅媒体释放剩余预占 |
| C11 | `POST /executions/{execution_id}/close` | `close_id, reason, expected_state_version` | 未执行则释放并关闭；已执行则只申请停止并等待最终费用 |
| C12 | `POST /transfers/{transfer_id}/prepare` | 企业、方向、`currency=CNY, amount_cny`、资金来源摘要 | 创建人民币增减余额操作；转出先冻结远端可退金额，转入不立即增加可消费余额 |
| C13 | `POST /transfers/{transfer_id}/commit` | 不可变 `decision_id, decision_hash` | 原子入账或扣减冻结转出资金，返回远端流水 |
| C14 | `GET /transfers/{transfer_id}` | 集成身份、资源权限 | 判断原操作是否成功，禁止用新的划转编号盲重试 |
| C15 | `POST /transfers/{transfer_id}/close` | `close_id, expected_state_version` | 未决定提交的划转关闭并释放；与 commit 竞争时只有一个结果胜出 |
| C16 | `GET /accounts/{enterprise_id}/ledger` | `after_sequence, limit` | 递增 `sequence` 的账务事件和同水位余额，支持消费/划转对账 |

每个列表页限制不超过 200 条，返回 `next_cursor` 或 `next_sequence`。404 仅表示该查询时刻未找到，不能证明另一条请求以后不会完成。

原稿 C04 价格目录和 C17 划转换汇报价接口已撤销，编号留空。既有接口能返回所需数据时优先补齐字段；表中包装路径不要求重复建设同功能接口。具体落到扩展原接口还是集成包装，在双方技术评审时确定。

### 6.1 执行入口与现有模型协议

新增执行入口 `POST /api/v1/integrations/sep/executions/{execution_id}/dispatch`，使用服务签名，并携带对应企业模型 Key 和执行票据。对话票据来自不占款的 register；媒体票据来自 prepare：

```text
Authorization: Bearer <对应企业/用途/版本的模型 Key>
X-SEP-Dispatch-Token: <不记录日志的一次性票据>
Idempotency-Key: <execution_id>
```

请求只携带已登记的 `request_ref`，不能临时换模型、参数、提示词、工具声明、参考文件或输出上限。对话 register 保存原模型请求完整字段，媒体报价保存规格和不可变输入引用；不通过“忽略未知字段”改变模型行为。登记请求快照不等于登记或冻结资金预算。

算力平台复用原有模型协议适配器，对话响应继续为原 JSON/SSE，图片返回结果或已受理资源，视频返回任务受理信息。SEP 向客户端的既有模型接口可保持不变，内部统一封装新执行入口。

算力平台必须原子登记 `DISPATCHING` 再发送供应商请求；同一执行编号只能派发一次。重复 dispatch：尚未派发时可由唯一处理者取得派发权；已派发则返回当前执行状态，不再次调用供应商，不保证重放原对话流。

取得派发权后崩溃，若不能证明供应商未执行，只能进入未知状态查询/对账，不能重新派发。流断开、HTTP 超时、进程重启都不能自动换编号重试模型。

旧 `/v1/chat/completions`、图片、视频执行入口必须拒绝带 `sep_settlement_v1` 的企业 Key 直接调用，防止绕过资金授权或发生新旧路径双扣。原任务查询/下载可继续使用已有协议，但必须检查企业/任务归属，不产生新的生成费。

## 7. 核心对象与请求字段

### 7.1 媒体报价与术语说明

原稿“预算报价”指执行前估算“预计费用、最多允许花多少”，原本用于计算预占金额；不是企业充值预算，也不是实际扣款。该步骤已从对话流程撤销。对话不必先估价或冻结金额才能发送请求。

图片/视频保留当前报价：按模型、操作、尺寸/分辨率、数量、质量/时长等取得金额，供现有媒体预占和参数校验使用。优先复用既有报价接口；集成包装 `POST /quotes` 只接受 `kind=image|video`，不增加独立模型价格目录。

响应必须包含：

```json
{
  "contract_version": 1,
  "quote_id": "quote_example",
  "request_ref": "request_example",
  "enterprise_id": "ent_example",
  "kind": "image",
  "model_id": "example-model",
  "price_version": "price_example_1",
  "currency": "CNY",
  "amount_cny": "7.200000",
  "max_gross_cny": "7.200000",
  "observed_at": "2026-11-20T00:00:00Z",
  "expires_at": "2026-11-20T00:01:00Z"
}
```

媒体执行使用有效报价，已过期不能 prepare，已 prepare 按冻结版本执行。对话由算力平台在受理时记录生效计费规则和汇率版本，结束后返回实际费用，不要求 SEP 查询价格目录，也不能让事后改价追溯影响这次调用。价格/消费展示从既有模型信息、媒体报价及实际费用结果读取；展示缺字段时先明确具体字段来源，不新增独立只读价格接口。

### 7.2 媒体预占与对话后结算授权

以下预占示例仅适用于图片、视频。SEP 在本地短事务内原子锁定免费赠送来源、企业资金及成员额度，生成 `free_hold_ref`、资金拆分摘要及待发送事件。事务提交后才请求远端 prepare，不在数据库锁内等待网络。

```json
{
  "contract_version": 1,
  "enterprise_id": "ent_example",
  "quote_id": "quote_example",
  "request_ref": "request_example",
  "free_hold_ref": "free_hold_example",
  "currency": "CNY",
  "max_free_cny": "2.880000",
  "max_paid_cny": "4.320000",
  "funding_hash": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa"
}
```

`max_free_cny + max_paid_cny = quote.max_gross_cny`。免费预算来自本地真实已预占权益，不能接受客户端提供的免费金额。算力平台检查集成身份、企业、报价、用途、Key、人民币预占额及当前人民币可用付费余额，并在单次本地事务中创建预占记录和执行资源。

媒体全免费执行 `max_paid_cny=0` 时，企业付费余额为 0 也应允许已授权执行。对话 register 只证明 SEP 已完成准入检查，不承诺某一份免费额度已锁定；不传 `free_hold_ref/max_free_cny/max_paid_cny`，远端不提前扣款或冻结资金。实际免费/付费分配以 SEP 后台结算决定为准。原有中间件不能仅因付费余额为 0 就拒绝 SEP 授权的免费使用；报价、账务查询、原任务查询和下载也不能因余额见底而失去查询能力。

算力平台可验证集成身份、记录免费消费和审计，不能接受客户端声明的免费金额。媒体未完成预占不得派发；对话不要求预占，免费消费在 SEP 实际结算事务中确定，远端收到可信 commit 后才记录免扣部分。

### 7.3 最终费用单

“最终费用单”就是“这一次实际用了多少、按算力平台的价格实际应计多少钱”的结果，不是新增收费项目，也不是要求用户另买账单。优先扩展已有实际消费/账务查询能力；缺少对话按请求查询实际金额时再补齐该能力。这里只要求可靠数据，不强制另建重复服务。

费用单独立于模型成功/失败状态：失败请求也必须确认是否产生费用，不能见 HTTP 错误就归零。对话流中的 usage 供展示和排障，不能替代算力平台最终费用单。

`GET .../bill` 返回 `fee_status=pending` 时 `gross_cny=null`；完成时返回已由算力平台换算的人民币费用：

```json
{
  "contract_version": 1,
  "execution_id": "exec_example",
  "enterprise_id": "ent_example",
  "bill_id": "bill_example",
  "bill_version": 1,
  "bill_hash": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "fee_status": "final",
  "currency": "CNY",
  "gross_cny": "7.200000",
  "price_version": "price_example_1",
  "usage": { "input_tokens": 1000, "output_tokens": 1000 },
  "execution_status": "COMPLETED",
  "settlement_status": "UNCOMMITTED",
  "compute_request_id": "compute_example",
  "provider_request_id": null,
  "task_id": null,
  "finalized_at": "2026-11-20T00:00:30Z"
}
```

必须附带可追溯的费用组成、实际用量和最终模型信息；图片/视频包括实际数量及计费维度。上例省略费用组成仅为展示共同字段，具体组成由算力价格契约返回，SEP 不按组成重算费用。

`final` 表示人民币实际费用已确定，不表示已经扣企业付费余额。`gross_cny=0.000000` 必须是经确认的零费用，不能把 missing/pending 解释为零。算力平台可附美元成本和换算版本供审计，但 SEP 的结算只依赖确认的人民币金额。

仅媒体最终费用受 prepare 金额约束，异常超额标记 `BUDGET_BREACH` 隔离对账。对话没有执行前资金预算，不适用该限制；其执行后余额不足按当前欠费规则记录，不能把预算上限要求变相加回对话。

费用单一旦 final 不可覆盖。后续冲正通过单独的关联调整单完成，不修改旧单、复用旧 commit 或直接改余额；调整接口作为双方确认的后续扩展，上线前至少有受控人工工单和关联账务流程。

### 7.4 结算确认

媒体按原预占公式确定拆分并保存决定。对话则在后台取得实际费用后，通过本地事务实际扣减免费权益及资金、写账单和 outbox；资金收齐时保存不可变完整结算决定。远端根据这个决定扣对应付费部分，不能从对话 usage 自行再扣全额。`commit` 共同字段如下，实际接口还需标明 `settlement_mode`：

```json
{
  "contract_version": 1,
  "enterprise_id": "ent_example",
  "settlement_id": "settlement_example",
  "settlement_mode": "media_reserved",
  "bill_id": "bill_example",
  "bill_version": 1,
  "bill_hash": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
  "decision_hash": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
  "currency": "CNY",
  "gross_cny": "7.200000",
  "free_cny": "2.880000",
  "paid_cny": "4.320000"
}
```

算力平台校验人民币总费用与自身 final 单相等、SEP 集成签名可信、人民币拆分守恒一致。SEP 不提交美元分摊或自行指定汇率。媒体额外校验原预占上限，消耗预占并释放剩余；对话根据 SEP 已确认的人民币实际付费金额扣远端对应资金权益，不要求请求前冻结。内部需要换算或处理余差时由算力平台负责，不能反过来改写已确认的人民币拆分。余额不足则保持未确认并对账，不伪造 COMMITTED。免费部分不减少账号付费余额或付费 Key 配额。

媒体收到远端 `COMMITTED` 后把本地预占转为实际消费。对话本地已扣款的，收到确认后只更新同步状态，不再次扣本地余额。远端失败或响应丢失时重放原决定或查询，已扣待同步金额保留账务证据，不自动退款；未收齐的欠费不提交为已全额付款。远端尚未确认时不能展示为双边已完成。

回执至少包含 `execution_id, settlement_id, decision_hash, status, ledger_sequence, ledger_entry_id, currency=CNY, charged_paid_cny, recorded_free_cny, committed_at`。零付费也必须返回结算回执，不能跳过免费权益记账。

### 7.5 摘要和版本

`funding_hash/bill_hash/decision_hash` 为 SHA256 小写十六进制。费用单和决定使用双方冻结的固定字段顺序编码规则：字段按 schema 顺序、金额保留规定小数位、UTF-8、无空白、禁止额外字段、可空字段显式 null。计算时排除摘要自身、HTTP 签名及传输重试时间，禁止循环包含自身摘要。业务创建时间及最终费用确认时间属于不可变内容，不随重试改写。

实现前把完整对象 schema 与字节级摘要测试向量一同冻结；不能用各语言默认 JSON 序列化器各算各的摘要。本稿的示例摘要是人工占位标记，不可作为签名测试向量。配套校验脚本只验证金额、预算和文档 JSON，不证明协议签名或跨平台事务已实现。

`state_version` 从 1 递增。状态变更条件以数据库版本更新为准，不能依赖单进程内存锁。幂等比较包含版本、主体及规范化业务内容；追踪时间、nonce、HTTP 签名不属于业务幂等内容。

## 8. 状态机与释放边界

执行、费用和结算使用独立状态，不把 `COMPLETED` 等同于已收费。

| 维度 | 状态及允许变化 |
|---|---|
| 执行 | `NOT_DISPATCHED -> DISPATCHING -> ACCEPTED/RUNNING -> COMPLETED/FAILED/CANCELLED`；无法确定受理结果则 `SUBMISSION_UNKNOWN` |
| 费用 | `PENDING -> FINAL`；异常 `RECONCILING`，不能通过超时自行置零 |
| 媒体结算 | `PREPARED -> COMMIT_PENDING -> COMMITTED`；确认未执行可 `PREPARED -> RELEASED`；异常保留 `RECONCILING` |
| SEP 媒体本地 | `LOCAL_HELD -> REMOTE_PREPARED -> EXECUTING -> BILL_FINAL -> COMMIT_DECIDED -> REMOTE_COMMITTED -> SETTLED` |
| SEP 对话本地 | `REGISTERED -> EXECUTING -> BILL_FINAL -> LOCAL_CHARGED -> COMMIT_DECIDED -> REMOTE_COMMITTED -> SETTLED`；不足额则 `UNPAID/RECONCILING`，不伪装已全额结清 |

媒体 prepare 有效派发期限默认 120 秒，只限制“允许开始派发”的时间。未取得派发权且已过期，算力平台原子关闭并释放远端冻结；取得派发权后不能按 TTL 自动释放。长视频不得因运行超过 120 秒退占款。对话 register 没有资金冻结，票据过期只阻止新的派发，不存在预占退款。

`close` 必须与 dispatch/commit 在同一资源上竞争状态：

- 从未派发：关闭资源并返回不可逆终态；媒体取得 `RELEASED` 证明后释放本地额度，对话无请求前预占可退。
- 执行中：返回 202 `STOP_REQUESTED`，等待算力确认停止及最终费用单；可能已经产生费用。
- 已有最终费用：按费用单结算，不能用 close 清零已发生费用。
- 未找到执行资源：创建持久化关闭墓碑，阻止同编号延迟 prepare/dispatch 后到，返回可验证的关闭结果；不能简单返回 404 后就退款。
- 已 `COMMIT_DECIDED/COMMITTED`：不得与释放竞争成两个成功结果。查询/重放原决定或单独走后续冲正流程。

媒体本地预占成功、远端 prepare 响应丢失时，先查询或 close 原执行编号，取得终态证明才释放；不能因查询瞬时 404 就释放。对话 register/dispatch 响应丢失同样查原执行单，但没有预占资金退款动作。离线时间较长只告警/暂停有风险的新消费，不删除未确认账务。

## 9. 充值、退回及资金来源映射

### 9.1 划转协议

`direction=CREDIT_COMPUTE|DEBIT_COMPUTE`，请求只传人民币 `currency=CNY, amount_cny` 和资金来源，金额为正，方向单独表示。SEP 转入 100 元，算力平台确认入账人民币权益 100 元；退回 20 元，远端确认减少人民币权益 20 元后，SEP 才恢复对应钱包可用额。算力平台内部如需买入/释放美元余额自行处理，不要求 SEP 请求换汇报价或提交美元金额。

`prepare` 请求包含企业、方向、人民币金额及 `funding_ref`；返回预备状态、确定的人民币金额与冻结明细。全额退出按查询到的可退人民币权益及状态版本处理，不能退已预占或超出原现金权益的金额。SEP 原子预留本地资金并建立待办事件，再发远端 prepare；收到成功后保存不可变提交决定，再发远端 commit，最后完成本地过账。

转入仅在远端 commit 后变为算力可消费余额，本地未收尾前不允许新任务花这笔在途资金。转出必须从未被消费/转出预占的远端余额中冻结，确认远端 commit 后才能在 SEP 恢复为钱包自由余额。

提交响应丢失时用原 `transfer_id` 查询/重放；`close` 同样必须有阻断延迟 prepare 的墓碑，已保存提交决定的 SEP 不再发送 close。算力账号的余额变更与划转回执、流水在同一数据库事务完成。

### 9.2 不重复映射

企业公共算力资金分配给成员，是同一资金池内部的归属变化，不再次增加算力平台余额。赠送额度是免费权益，不给算力平台付费余额充值。

当前企业钱包 `balance` 已包含 `computeReservedCNY`，不能把两者相加当作两份余额。迁移时需要识别企业公共算力资金和已经转给成员的未消费资金，建立唯一来源映射；不能把整个企业钱包都自动划给算力平台。

个人钱包目前可能替成员支付，但不属于企业资产。本协议定义资金摘要可区分 `enterprise/member/personal`，不授权把个人资金永久转为可由企业管理员退走的余额。个人兜底的资金转入、按单托管及原路退款规则尚待业务确定；在确定之前不得让新模式静默沿用旧的个人兜底或默默关闭它。相关企业应保持旧模式，直到所需资金来源完成接入后整体切换。

## 10. 并发、幂等与故障恢复

### 10.1 必须满足的本地原子边界

SEP 媒体：免费权益/付费资金预占 + 成员额度预占 + 执行单 + outbox 同事务；结算决定 + outbox 同事务；最终资金结转 + 用量账单 + inbox 去重同事务。

SEP 对话：开始按当前实现检查余额并创建执行记录，不冻结资金。后台结算时，免费权益实际消耗 + 资金实际扣减 + 欠费记录 + 用量账单 + 待同步事件在同一事务中完成；完整结算决定与 outbox 同事务，重复处理只复用原结果，不重复扣款。

算力平台：仅媒体在同一事务中检查账号可用额、创建预占及 prepare 资源；对话只登记请求。dispatch 处理权通过持久化唯一条件取得。两类最终扣款、免费用量、流水及 commit 回执均在本地同一事务完成，只有媒体存在“释放剩余预算”。

固定顺序获取企业资金、成员资金、赠送来源等锁；资金扣减使用金额条件和版本校验。模型执行、上传、网络等待绝不能保持数据库行锁。多个服务实例通过数据库约束/租约协调，不能只用内存变量保证安全。

### 10.2 幂等规则

同一个业务 ID 同参重试返回原状态，不重复派发、充值、扣款、退款。不同内容复用业务 ID 返回 409 `IDEMPOTENCY_CONFLICT`，不能覆盖原单。媒体免费预占引用不可重复登记；对话免费权益在结算事务内实际消耗，不能复用发送前的余额快照。双方执行单、结算单、划转单和远端账单关联均有唯一约束。

投递采用至少一次、消费端幂等。工作进程通过有限期租约领取待办；租约失效只允许接管“查询/重放账务确认”，不允许重新生成模型。普通重试建议指数退避加抖动，最大间隔 60 秒；超过 15 分钟告警，未解决事件仍保留，不能因达到重试次数就丢弃。

### 10.3 恢复矩阵

| 故障位置 | 唯一允许的恢复动作 |
|---|---|
| 媒体本地预占事务失败 | 不请求远端 prepare/dispatch |
| 媒体本地已预占，远端 prepare 超时 | 查询同执行单；必要时 close 并取得终态证明，再释放本地 |
| 媒体远端已预占，SEP 未保存响应 | 查询同执行单恢复，不能再次生成新执行单 |
| 对话 register 超时 | 查询原执行单；不为“恢复”增加资金预占，不重复派发模型 |
| dispatch 超时或流断开 | 查询执行/最终费用；不默认没执行，不换编号重发 |
| 已执行，最终费用未就绪 | 媒体保留双方预占；对话保持待结算、后台查询，不按 usage 或本地价格提前扣费 |
| 对话本地已扣款，远端未确认 | 保存已扣与待同步金额，查原单/重放原决定，不再次本地扣款或自动退款 |
| 对话执行后余额不足 | 按当前方式记录欠费；未收金额不得让远端当作已付扣减，补齐后再完整确认 |
| SEP 已保存结算决定，commit 请求超时 | 重放相同 commit 或查询；不得回滚成免费或退款 |
| 远端已扣款，SEP 收尾失败 | 根据远端回执完成本地资金结转；不能再次远端扣费 |
| 本地已完成，远端确认响应再次到达 | 幂等返回原账单，不重复修改余额 |
| 转出冻结与模型预占同时发生 | 由同账户可用额事务条件决定成功者，不让同一资金重复使用 |
| 检测到金额、版本或主体不匹配 | 隔离该单、保留媒体占款或对话已扣待同步记录并告警，查询仍可用 |

## 11. 错误与可观测性

控制接口统一非 2xx 错误结构；模型协议错误继续保留真实上游诊断并对凭证脱敏，不将所有失败改写为 `MEDIA_FAILED` 或统一 500。

```json
{
  "contract_version": 1,
  "error": {
    "code": "BILL_NOT_FINAL",
    "message": "实际费用尚未确认，请查询原执行单",
    "source": "compute",
    "stage": "settlement",
    "retryable": true,
    "next_action": "query_original",
    "execution_id": "exec_example",
    "request_id": "trace_example"
  }
}
```

`retryable` 只表示该步骤可按同一业务 ID 恢复，不授权重新执行模型。推荐错误码：

| HTTP | code | 处理 |
|---|---|---|
| 400/422 | `INVALID_CONTRACT` / `SPEC_UNSUPPORTED` | 明确字段；媒体修正后重新报价，对话修正原请求，禁止盲重试错误参数 |
| 401/403 | `INTEGRATION_AUTH_FAILED` / `ACCOUNT_BINDING_MISMATCH` / `KEY_KIND_MISMATCH` | 不回退平台 Key，不把上游认证失败当客户端退出登录 |
| 409 | `IDEMPOTENCY_CONFLICT` / `STATE_CONFLICT` / `ALREADY_DISPATCHED` | 查询原单，禁止覆盖或重发模型 |
| 409 | `QUOTE_EXPIRED` / `PRICE_VERSION_CHANGED` | 媒体未执行时重新报价和预占；对话不引入报价/预占，已执行保留受理时规则 |
| 409 | `BILL_NOT_FINAL` / `SETTLEMENT_MISMATCH` / `FX_VERSION_MISMATCH` | 原单查询或隔离，不先释放资金 |
| 409 | `INSUFFICIENT_PAID_FUNDS` / `FREE_AUTHORIZATION_INVALID` / `BUDGET_BREACH` | 按阶段处理；预算超额只适用于媒体，对话结算不足保留欠费/待对账，不伪造扣款成功 |
| 429/503 | `RATE_LIMITED` / `SERVICE_UNAVAILABLE` | 读取 `Retry-After`，带原业务编号恢复 |

执行资源查询必须返回 `execution_status, fee_status, settlement_status, state_version`，即使没有费用也明确 `pending/final`。签名或租户校验失败时错误不泄露其他企业资源是否存在。

日志记录企业、执行单、费用单、结算单、划转单、远端追踪编号及失败阶段；不记录 Key、执行票据、签名、完整签名下载 URL、完整提示词或文件内容。指标至少覆盖预占年龄、待结算金额、未完成划转、余额差异、重复请求、免费使用量及对账延迟。

## 12. 对账与人工处理

SEP 主动扫描本地待办，同时按远端账户账务 `sequence` 拉取；查询游标必须落库，不能只看过去几分钟的时间窗口。跨页重放不重复入账；断档先补齐，不跳过无法解释的事件。

每日按人民币核对每个企业的已确认转入转出、远端人民币可用/冻结权益、免费消费、付费消费及划转，并排除尚在途的不同水位差额。SEP 不核算对应美元余额；美元成本及换算余差由算力平台自行核对。发现未绑定执行单的扣费不得盲扣任意用户，保留凭证并进入异常工单。

双方集成账号的正常余额只允许通过本协议变化。算力平台后台人工调账、用户直接充值或其他协议消费必须禁止绕过，或产生可关联的独立调整事件并由 SEP 确认归属；不能静默破坏映射。

人工处理必须记录执行人、原因、证据、原单、关联调整单及双方流水。不得通过删除账单、改写 final 金额或直接 SQL 修改余额“对平”。

## 13. 实施边界与切换

1. 算力平台实现分用途凭证、媒体既有报价的必要补充、按请求确认实际费用、免费授权及幂等结算。对话只登记后执行，不增加独立只读价格目录、预算报价或请求前资金冻结。
2. SEP 增加企业连接解析和实际费用同步。对话保留“余额检查、执行、后台后扣款”，媒体保留已有预占。覆盖客户端网关、Web 对话、数字员工、企业任务规划/交付等实际企业计费路径，不能只改一个 controller。
3. 平台自身模型测试、内容生成和配置报价校验使用平台明确的账号/凭证，不任意归到某家企业。知识库 embeddings 是否纳入企业计费属于范围确认项，不能默默漏记或改用企业聊天 Key。
4. 不新增独立价格查询接口，SEP 不新增改价入口。已有页面需要展示的价格从算力平台既有模型信息、媒体报价或实际费用结果取得；字段不够先确认扩展来源。继续管理模型权限、规格、默认参数和资金。
5. 数据库改造在实现阶段生成新迁移，不改历史迁移。当前阶段只交付契约及演算样例。
6. 切换按企业生效，禁止一个企业的新请求在新旧模式间自动回退。先盘点、冻结切换窗口、处理旧在途任务与账单，再建立资金映射；已有企业资金进入算力账号只能记一次迁移入账。
7. 老执行单按原模式完成，不能因发布新版本重新收费或追溯改为新价格。发布不删除原账务证据；回滚有未完成新单时保留新协议查询/结算能力，只停新单准入。

## 14. 双方联调验收清单

- [ ] 同企业并发开户只建一个账号及三种用途凭证；邮箱重复不自动绑定其他企业账号。
- [ ] Key 用途混用、跨企业执行、伪造免费金额、绕过 dispatch 均被拒绝。
- [ ] 免费覆盖全部时远端余额 0 也能执行，双方付费余额不变，免费权益仅消耗一次。
- [ ] 免费覆盖部分时按实际费用拆分，媒体退回未使用预占；对话无预占可退，后结算不重复消费免费权益。
- [ ] 媒体并发预占不重复占款；对话允许并发通过余额检查，结算事务不得重复扣免费额度或覆盖余额，余额不足明确记录欠费。
- [ ] 对话包含缓存、工具、长上下文等计费维度时，SEP 只使用最终费用单，不走本地价格表。
- [ ] 不存在新增独立价格目录及对话预算报价/预占依赖；实际费用查询失败时待对账，不能使用本地价格兜底扣款。
- [ ] SSE 断流、供应商失败、视频运行跨天和查询时余额耗尽仍能确认费用及读取原结果。
- [ ] dispatch/commit/transfer 任一响应丢失，重试不重复生成、不重复充值、不重复扣减。
- [ ] 媒体 prepare 延迟与 close 竞争时墓碑有效；对话 register/close 竞争也不能重复派发，但不得引入预占。
- [ ] 任一阶段进程被终止后可接管恢复；过期租约不会重新派发供应商请求。
- [ ] 双方金额统一 CNY；0.000001 元、小额多笔、部分免费及全额转出守恒。SEP 不乘汇率或维护美元映射；算力平台内部换汇和汇率变化不改变已确认人民币账单及资金权益。
- [ ] 账务列表同水位可重放，重复页、游标恢复及人工调整不漏单、不重复入账。
- [ ] Key 轮换、企业停用/删除过程中仍可受控结清旧单，不能丢失占款或恢复新执行权限。
- [ ] 旧在途任务、新企业开户、现有资金映射和异常回滚均有独立切换验证。

## 15. 实现前必须冻结的技术决议

本节不是重新讨论已确定业务边界；以下值/细节没有在此前对话中确定，不能伪装成已获确认：

| 决议 | 本稿建议/所需结果 |
|---|---|
| 算力平台人民币结算能力 | 换汇明确由算力平台管理；确认其人民币余额、冻结、费用和流水是真实可结算权益，不能只返回随当前汇率浮动的展示值 |
| 人民币精度、余差及全额退出 | 双方冻结 CNY 6 位小数测试向量；内部换汇余差由算力平台处理，SEP 不承担美元账本和换汇算法 |
| 完整对象 schema、摘要字节向量 | 区分不预占的对话和媒体协议，固定 request/媒体 quote/bill/decision/receipt 字段 |
| 对话欠费补收与退回竞争 | 不增加请求前预占；明确未收齐时的同步状态、补收入口及在途消费后的转出不足处理，不能宣称不存在超用风险 |
| 个人钱包支付 | 明确按单资金托管或其他隔离办法，不能成为企业可退资产 |
| 用户自主停用/注销与企业删除 | 先停止新任务，保留受限结算通道，明确在途任务处置，不物理删除未结账务 |
| embeddings 和平台自用请求 | 分别确认是否计企业费及使用哪个账号，不能默认属于三类企业 Key |
| 免费授权运营边界 | 双方登记可授予免费权益的集成身份、限额和审计责任，不沿用旧 `isFree` 绕过新结算 |
| 资源保留及故障恢复目标 | 确认账务保留期、输入文件 TTL、恢复时限及人工工单责任方 |

业务原则可直接用于双方评审；完成这些技术决议、完整 schema 及故障联调后，协议才标记为 `v1-frozen`。不能将本文新增路径当作已部署能力。
