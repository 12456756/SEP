## 需修正的目录行为

`GET /v1/models` 已被 SEP 用作企业模型偏好和图片/视频授权的候选集合，请补入正式接口文档，明确需要用途 Key + 服务签名 + 企业编号。

你方 `GatewayHandler.Models` 仍沿用普通目录逻辑，没有在此处按 SEP chat/image/video 用途过滤，并会在空目录时返回平台默认模型。这会让 SEP 展示不属于当前用途、甚至没有真实上游资源的模型。

请为 SEP 请求只返回该 Key 对应用途、实际有权限且可路由的模型；空目录返回空数组，降级目录明确标记。最多 2000 条之外的分页需另行约定，不能静默截断。

本次联调通过为三个专用分组分别配置 `models_list_config` 取得正确目录；这只是测试分组的明确限制，不代表通用目录问题已经消除。

## 管理员校验凭证已确认

我们继续采用用户已确认的管理员账号模型 Key，经原图片/视频 pricing 接口校验。已用 SEP 的真实适配器验证可用、不会发起生成，返回旧 USD 报价仅用于配置校验。

请在文档区分：

- 管理员普通模型 Key → 原 pricing 接口，配置校验，不借企业 Key。

管理员 Key 不是登录 token 或管理 API Key，也不替代开户、充值、免扣授权的 SEP 服务签名。

## 请在接口文档强调

1. N01 原单恢复必须保留原企业名称、管理员邮箱和加密版本；N02 没有密文，交付恢复依赖原 POST 重放。SEP 已持久化开户快照。
2. N05 回执没有 bill_version/account_id；SEP 已通过 N04 final 单和 N02 账号关联核对。后续加字段须明确版本，不假设当前已经返回。
3. N06/N07 的 200 rejected 是持久化业务拒绝。SEP 已处理为终态失败，而非成功或无限重试。
4. 账号 ID 当前是 JSON 整数，若将来超过 JavaScript 安全整数范围，请改成十进制字符串并发布契约变更。
5. 服务签名只有一个活动版本，换公钥需协调；关闭集成也会关闭旧账和任务查询。
6. 部分非 SEPError 在 handler 仍被统一为 SEP_STORAGE_UNAVAILABLE，请补脱敏后的具体诊断和请求追踪编号，避免真实原因继续被丢弃。
