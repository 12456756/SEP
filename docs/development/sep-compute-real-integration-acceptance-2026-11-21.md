## 3. 需要处理的问题

### A. SEP 对话仍受旧平台模型表限制

企业 Key 的目录返回 `gpt-6-luna`，但 SEP 网关先查旧表，缺少该模型记录即返回 HTTP 400、`MODEL_UNAVAILABLE`、提示“该模型未启用或已下架”。补入一条本地测试元数据后请求才通过。

定位：`backend/src/modules/gateway/gateway-model-policy.service.ts:113` 的 `platformModel.findFirst`，以及第 118 行的拒绝逻辑。需要明确企业模式下的准入应以企业目录及企业/部门限制为准，旧平台表是否只负责补充展示信息。本轮未修改该逻辑。

### B. 视频提交在当前上游链路失败

实测响应：

```json
{"error":{"message":"X-Video-Operation must be text-to-video or image-to-video","source":"platform","type":"invalid_request_error"}}
```

报价校验、企业报价都成功；失败发生在生成提交阶段。此前进度描述中若称为报价失败，以本报告为准。

SEP `backend/src/modules/media-gateway/sub2api-video.adapter.ts:155` 已设置 `X-Video-Operation`，签名传输层保留该头。算力平台 `backend/internal/service/openai_videos.go:352` 附近构建上游请求时设置认证、内容类型和幂等头，但没有转发该操作头。当前上游是另一层在线网关，其错误文本与对操作头的校验一致。

因此源码支持的原因推断是：本地算力平台向在线网关转发时遗漏了操作头。没有抓取在线网关内部日志，仍应由算力方结合请求追踪确认；不要把推断写成供应商已证实的事实。

两笔原回执：

- 文生视频：`cmwq593m100bnvf2otj51ux7e`，执行 `cmwq593mh00bovf2og36tx7c1`。
- 图生视频：`cmwq594it00c2vf2oy97f4axw`，执行 `cmwq594j600c3vf2out3e6fkf`。

两笔均可按原编号找回，但尚未确认最终失败或产生供应商任务，远端状态为 unknown/pending。SEP 各保留 13.213200 CNY、合计 26.426400 CNY 的本地预占，没有强行释放或重新生成。后续应先查清原请求再恢复，不能直接换编号重试。

### C. 可登录企业账户仍有旧式受管账户判断

算力平台普通管理接口对新建企业账户充值：`POST /api/v1/admin/users/52/balance`，返回 HTTP 500、`internal error`，两边余额均未变化。该账户创建额外普通 Key 也返回相同的笼统 500。

充值路径源码：算力平台 `backend/internal/service/admin_user.go:473` 仍按 `PasswordHash == "!sep-service-account"` 判断受管账户；新开户使用 bcrypt，绕过此业务拦截。但 `backend/migrations/191_sep_login_accounts.sql:2` 起的数据库保护函数依然禁止对 SEP 绑定账户直接改余额，最终形成数据库拒绝及通用 500。

应改为根据企业绑定判断账户管理方式，并返回明确业务错误；若要允许独立充值，应先完善第 25 项账务契约。额外 Key 创建只确认了受阻和错误不明确，未在本报告中指定其完整调用栈。

### D. 独立算力余额变化不会反向入账到 SEP

需要区分以下两种情况：

1. **由 SEP 发起**的划入、退回，以及本轮正常对话和图片消费：存在双方可匹配业务编号，已验证双边记账及对账。
2. **只在算力侧发生**、SEP 没有本地业务记录的余额变动：当前没有自动导入 SEP 钱包或成员资金的处理。

边界实测使用另一个隔离测试企业、合法服务签名的控制划转接口，远端余额从 0 增至 1.000000 CNY，SEP 保持 0；实际运行对账后记录 `DIFFERENCE`、差额 -1.000000，并标识未知划转。随后用反向远端划转恢复余额至 0，保留两笔证据流水。此测试不等于普通后台充值成功，也不是实际供应商独立消费测试。

SEP `backend/src/modules/compute-integration/compute-reconciliation.worker.ts:58` 起仅根据已有本地划转、结算记录核对远端流水；第 86 行起保存差异，不会据此增减企业钱包或成员余额。反向划转即便使净余额归零，未知流水仍可能使对账保持差异。

若产品要求“可以在算力平台直接充值或消费，两边自动一致”，现有方案尚不满足。需双方约定算力侧事件或流水导入、资金归属、幂等落账与失败补偿后再开发；不能只把远端余额覆盖到 SEP，也不能把退回测试金额的操作描述成独立消费已完成。
