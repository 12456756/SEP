# 企业模型校验移除旧模型管理依赖

日期：2026-11-23。

## 行为变化

企业模型可选范围及客户端网关调用校验，以企业对话 Key 的模型目录和企业、部门策略交集为准。旧 `platform_models` 表的缺失记录、启用状态、失效状态、类别及能力字段不再决定这条链路的模型是否允许调用。

- `compute-model-catalog.service.ts`：不再读取旧模型表；仍排除图片专用模型和已配置的媒体模型，模型目录来源和用途过滤由算力平台负责。旧表提供的展示及能力补充字段现返回 null，名称沿用企业目录。
- `gateway-model-policy.service.ts`：移除旧模型存在性、启用/失效、工具调用、图片输入、流式和单模型输出能力校验。保留企业/成员/订阅授权、模型策略交集、请求大小及平台统一输出限制。具体模型能力由上游判断并通过现有错误链路返回。
- `client.service.ts`：运行配置中的允许模型和默认模型使用与网关相同的企业策略解析结果。
- `conversation.service.ts`：网页会话切换模型校验企业 Key 及企业、部门限制，同时检查归属和切换开关。
- 网页对话、员工运行器、任务规划、任务交付物汇总和能力分析：不再读取旧模型表的输出上限，继续执行运行策略中配置的默认值和统一上限。

本次没有删除模型管理页面、管理接口或历史数据，也没有改数据库结构、价格、免费额度或账务规则。其他旧模式的模型管理及计费代码仍保留，不将本次改动描述为整个旧模块已经卸载。

## 验证

新增会话切换权限测试，调整目录、网关、客户端运行配置及内部调用的回归用例，覆盖缺记录、旧表禁用/失效、过期能力值不再拦截，以及企业/部门范围、空目录、强制默认和资源限制仍生效。

- 12 个相关后端测试文件通过，首次合计 310 个测试；补充客户端运行配置用例后，该文件单独重跑 41 个测试通过，比前次增加 1 个用例。
- 与本次相关的网关 HTTP 选择性测试 11 个通过。
- 最终重跑整个网关 HTTP 文件：44 个通过、8 个失败，失败范围与下述基线复测一致。
- `pnpm --dir backend typecheck` 通过。
- `pnpm --dir backend exec nest build` 通过，webpack 编译成功。
- `git diff --check` 通过。
- 标准 `pnpm --dir backend build` 在编译前被头像资源检查拒绝：`Avatar registry is stale`。未为通过该检查而改动无关资源。

网关 HTTP 全文件首轮发现 8 条与错误透传及 SSE 断流有关的断言失败。使用 Git HEAD 中本次修改前的网关模型策略类，通过临时测试映射重跑同 8 条，全部仍失败；已经移除临时类和配置。本次没有放宽断言或修改这些错误处理路径，不能声称整个 HTTP 文件或全量测试通过。

本轮未再次调用真实供应商生成、未修改本地账务数据、未启动或重启本地联调服务。变更尚未提交、合并或部署。
