# 算力 v1 接口核对与本地联调计划

依据：`D:/github/LongdaoAI-worktree-one/docs/development/sep-compute-platform-api-v1.md`，2026-11-20。

1. 核对远端文档、实际路由和实现，记录管理员校验认证、模型目录、金额、回执、开户重试等差异。
2. SEP 增加集中签名 HTTP 客户端及 JWE 凭证解密，复用 Node 标准加密库，不新增依赖。签名按实际发送字节计算，禁止重定向和自动重发生成。
3. 实现 N01/N02/N04–N09 控制适配；校验归属及金额；HTTP 200 的 rejected 划转作为终态失败。新执行和实际钱包仍保持未启用。
4. 将企业 `/v1/models` 接入签名；冻结首次开户资料与加密版本，原编号恢复时不改请求。为测试允许显式配置的非生产 loopback HTTP，正式环境继续 HTTPS。
5. 单测验证签名篡改、JWE 篡改/归属、回执和拒绝；隔离数据库验证；连接本机实际算力服务，以模拟供应商验证开户、目录、免费/混合结算、划转、流水，不触发真实费用。
6. 交付接口补充、开发完成矩阵、实际联调结果和剩余阻断。不能把控制接口联调通过当作所有用户调用、资金事务及生产切换完成。

管理员 Key 报价校验是用户已确认的方案。远端新增“仅服务签名的内部校验身份”与此不同，本批不默默切换认证方案；保留现有管理员 Key 校验，另将远端路径记录为待双方统一的替代方案。
