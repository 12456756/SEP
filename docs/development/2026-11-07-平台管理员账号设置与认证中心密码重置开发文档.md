# 平台管理员账号设置与认证中心密码重置开发文档

## 背景

平台管理员使用与普通用户相同的 `User`、`AuthCredential` 和认证接口。当前系统已有登录邮箱变更、登录密码修改、忘记密码邮件重置等后端流程；个人设置页面位于企业端路由组，并要求用户具有企业归属。平台管理员没有企业归属，因此无法通过现有页面维护自己的登录邮箱和密码。

认证中心的用户详情页已有“强制重置密码”操作。该操作通过邮箱发送一次性重置链接，并撤销用户会话，不支持管理员读取或直接设置用户密码。保留这一安全边界。

## 目标

1. 为平台管理员提供可发现的个人账号设置入口。
2. 管理员可查看当前登录邮箱和验证状态，可通过已存在的验证流程变更邮箱。
3. 管理员可输入当前密码并修改自己的登录密码。
4. 认证中心明确反馈强制重置请求成功或失败；只有重置邮件请求成功后才撤销目标用户会话。
5. 密码、重置令牌和邮箱变更令牌不回传、不展示、不写入浏览器持久化存储。

## 不在本次范围

- 管理员查看、读取或直接设置用户明文密码。
- 新增数据库字段、迁移或密码存储格式。
- 更改普通用户已有的个人资料页和认证协议。
- 增加平台管理员角色层级或管理员间的账号管理规则。

## 现有接口与行为

- `POST /auth/password/change`：当前登录用户提交当前密码和新密码；服务端校验当前密码并更新哈希，保留当前会话、撤销其他会话。
- `POST /auth/email/change/request`：当前登录用户提交新邮箱；服务端要求当前邮箱已验证，并向新邮箱发送确认链接。
- `POST /auth/email/change/confirm`：一次性令牌确认新邮箱；前端现有确认 hook 会刷新用户资料和内存认证用户。
- `POST /auth/email/verification/request`：向当前登录邮箱发送验证邮件。
- `POST /admin/auth/users/:id/force-password-reset`：平台管理员请求向目标用户发送重置邮件。
- `POST /auth/password/forgot` 与 `POST /auth/password/reset`：忘记密码和一次性令牌设置新密码流程。

接口均复用现有认证服务，不新增管理员专属密码写接口。

## 页面与交互

### 平台管理员账号设置

- 新增路由 `web/src/app/(platform)/admin/account/page.tsx`，继承 `(platform)` 布局已有的 `ADMIN` 角色限制。
- 在管理后台侧栏底部的账号信息区域增加清晰的“账号设置”入口，跳转到 `/admin/account`；折叠侧栏时提供可访问名称和 tooltip。
- 页面展示当前姓名、登录邮箱及邮箱验证状态。资料从 `GET /users/me` 获取，不把邮箱当作系统通知邮箱。
- 已验证邮箱时显示“修改登录邮箱”：输入新邮箱后调用现有请求 hook，提示确认邮件已发送；确认仍通过现有 `/verify-email-change` 页面完成。
- 邮箱确认页根据当前认证用户角色返回账号设置页：平台管理员返回 `/admin/account`，企业用户保留 `/settings/profile`。
- 未验证邮箱时显示验证状态和“发送验证邮件”操作，调用现有请求验证 hook。未验证前不开放邮箱变更表单，并说明需先完成当前邮箱验证。
- 显示“修改登录密码”表单：当前密码、新密码、确认新密码。沿用现有最小长度规则和 `useChangePassword()`；成功后清空表单并说明其他设备已退出。
- 所有提交显示 pending、成功和错误状态，防止重复提交。错误优先展示服务端 `ApiError.message`。
- 不将密码或令牌写入 query string、URL、Zustand、localStorage 或 sessionStorage。

### 认证中心重置密码

- 保留详情页“强制重置密码”操作，继续发送一次性邮件链接；界面明确说明操作对象会收到重置邮件并退出全部设备。
- 展示 mutation pending 状态；成功时明确提示邮件已提交发送，失败时展示接口错误；失败不得提示成功。
- 非 `ACTIVE` 用户不能发起该操作。生命周期状态和禁用状态均在前端禁用，并由后端重新校验。
- 服务端执行顺序调整为：读取并校验目标用户为 `ACTIVE` → 请求密码重置邮件 → 邮件请求成功后撤销全部有效会话 → 记录平台管理员操作审计。
- 平台管理员强制重置接口在邮件发送和会话撤销成功后返回明确的“密码重置邮件已发送”结果。
- 邮件请求抛错时保留现有会话，且不记录平台强制重置成功事件。继续使用统一密码重置 token，不返回临时密码。

- 修改 `web/src/components/shell/platform-shell.tsx`，为侧栏账号信息增加导航入口；更新现有 Shell 测试。
- 修改 `web/src/app/(platform)/admin/auth-users/[id]/page.tsx`，增加重置状态、结果反馈和可操作状态判断；添加详情页测试（若当前页面测试结构不适合，则将交互抽成可测组件）。
- 修改 `backend/src/modules/admin/admin-auth.service.ts`，校验目标状态并调整重置请求与会话撤销顺序。
- 修改 `backend/src/modules/admin/admin-auth.service.spec.ts`，覆盖成功顺序、邮件失败不撤销会话、非活动账号拒绝重置。

不改 Prisma schema，不新增依赖，不修改通用认证接口契约。

## 验收标准

1. 平台管理员从侧栏账号信息可进入 `/admin/account`；普通企业用户不会看到平台入口，也不能访问该平台页面。
2. 页面展示的邮箱和验证状态来自当前用户资料；已验证邮箱可以申请变更并通过现有确认链接生效；未验证邮箱可请求验证邮件。
3. 正确当前密码可修改密码，错误当前密码显示服务端错误；成功后确认表单已清空且其他会话已撤销。
4. 认证中心只对活动账号发起强制重置；成功时显示邮件请求结果并撤销会话，邮件发送失败时保留会话并显示错误。
5. 不存在管理员读取或设置他人明文密码的接口或 UI，不存在新增凭据明文存储。
6. 相关前端 Vitest、后端 Jest 测试和 Web TypeScript 检查通过；开发环境可打开实际管理后台页面验证入口与表单布局。

