# 企业算力业务接入实施计划

本次复用所有现有模型接口，不增加替代的生成接口。LEGACY 企业及已提交的旧媒体任务沿用原账务；仅明确启用 ENTERPRISE 的企业使用新契约。

1. 每个真实模型 HTTP 请求先保存执行关联、凭证版本、连接地址和付款身份，再发送签名请求。流式断线、超时和用量缺失都查询原执行费用，禁止自动重新生成。
2. 对话不预占。算力平台确认最终人民币费用后，现有账务事务按赠送、成员余额、企业钱包、个人钱包、欠费顺序记账，同时写入结算待办。Token 只用于明细；不再使用本地单价、倍率或汇率算钱。
3. 免费金额作为 free_cny，同步时不扣算力余额。付费部分作为 paid_cny。欠费未结清不提交 N05，不伪造免费费用。
4. 企业划入时本地锁住专款，远端确认后才能消费；划回在远端确认前不释放钱包可用余额。超时保留原流水重试，明确拒绝才补偿。成员内部划拨不重复充值远端。个人自费仅按已消费金额补入远端并绑定原流水，不能成为管理员可退回的钱。
5. 图片和视频保留现有 Profile、规格校验、报价、冻结、提交、查询、回执与内容接口。企业模式使用自己用途的 Key、人民币报价及 quote_id；查询固定原凭证和连接。
6. 后台持续恢复费用查询、结算和划转，按固定远端流水水位核对本地映射账本。差异仅记录告警，不自动改余额。
7. 测试覆盖并发赠送/钱包扣款、幂等、未知请求恢复、重复远端回执、划回并发、免费/混合/欠费、SDK 多轮请求以及真实本地跨平台调用。仅使用隔离数据库和测试账户。

事务顺序沿用 user -> enterprise -> 各资金来源；网络请求始终在数据库事务外。所有跨平台操作持久化编号及状态后重试。历史余额在切换前必须核对并补同步，禁止把未同步的旧资金当作远端已到账资金。
