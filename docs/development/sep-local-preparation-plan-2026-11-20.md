# SEP 可先行开发部分：实施方案

日期：2026-11-20。状态：已按用户确认开始实施，本地准备部分的完成情况见[开发交付说明](./sep-compute-local-delivery-2026-11-20.md)。远端接口仍未接通，新模式保持关闭。

接口依据：[给算力平台的最新交接文档](./sep-compute-platform-handoff-2026-11-20.md)。本文只规划 SEP 能先完成的部分，不把尚未确定的远端路径、签名或加密格式当成已完成接口。

## 1. 这批做完能得到什么

**先具备管理企业算力账号、正确选择企业 Key、追踪账务同步的基础能力，等待算力平台接口接通。**

管理员能看到企业是否开户、三类 Key 是否就绪、账务是否同步失败及具体原因。后端能按企业及用途解析连接，保存可恢复的请求和账务记录，并通过测试适配器验证流程。

这批完成不等于已经接通自动开户、人民币实际费用或真实双边扣款。现有调用及扣费继续使用原模式，新模式默认关闭。

## 2. 已确定且不能变的规则

- 一个企业对应一个算力账号，三个用途 Key，共用一份付费余额。
- 算力平台计算价格、实际费用和美元转人民币，SEP 直接接收人民币金额。
- SEP 不改价，不新增独立价格目录，不建立美元映射账本。
- 对话不增加执行前资金预占或估价，继续执行后后台扣款。
- 图片、视频保留已有报价与预占，后续接入人民币报价和实际费用。
- 免费覆盖部分不扣双方付费余额，付费部分由 SEP 确认后同步。
- 复用现有模型执行接口，不建设早期稿的 register/prepare/dispatch 新入口。

## 3. 第一批：企业账号、凭证和状态

### 做什么

1. 新增企业算力绑定数据，保存本地企业 ID、远端账号 ID、开户业务编号、开户状态、失败原因及最近同步时间。
2. 保存三类凭证的用途、远端编号、版本、密文和遮罩；同企业同用途只允许一个当前有效版本，保留原任务所需的历史引用。
3. 区分“账号和凭证已准备好”与“新模式已允许调用”，不能仅收到三个 Key 就自动启用。
4. 新模式支持按企业控制，默认仍使用原模式。开户未接通时明确显示未接通，不能用模拟返回把状态标成成功。

### 怎么落地

建议增加 `compute-integration` 后端模块，负责绑定、凭证及后续远端适配，避免将它们散落到聊天、图片、视频模块。

沿用现有 `secret-cipher` 加密封装；新凭证入口必须强制密文落库并拒绝明文回退。密钥由部署配置提供，不写进数据库或 Git。远端凭证交付的解密适配等双方确认格式后再接入。

新增结构与旧 `ComputeAccount` 隔离；旧模型有废弃 Float 余额字段，不能把它恢复为新资金主账本。原企业钱包仍是本地人民币资金来源账。

### 验收

跨企业不能读到其他绑定；重复准备不产生多个有效绑定；凭证不出现在接口、日志和测试快照中；账号就绪但结算未就绪的企业不能进入新模式。

## 4. 第二批：统一企业连接选择和请求关联

### 做什么

建立统一连接解析入口：输入可信企业身份和 `chat/image/video` 用途，返回服务器内部使用的地址、Key 和版本。

| 使用场景 | 连接来源 |
|---|---|
| 原模式企业 | 继续使用原平台配置 |
| 已正式启用新模式的企业 | 使用该企业对应用途 Key |
| 新模式企业凭证缺失或不可用 | 返回具体配置错误，不能自动借平台或其他企业 Key |
| 平台模型测试、图片视频参数校验 | 明确使用平台专用连接，不归到某家企业 |

解析器区分“查询原任务”和“创建新任务”，保留原任务的企业、凭证版本和请求关联信息，不能轮换 Key 后查询错账号。

所有真实企业调用入口都纳入清单：客户端聊天、Web 对话、数字员工、企业规划/交付，以及企业图片视频；不能只改客户端 controller。知识库 embeddings 是否纳入另行确认，不在本批自动改其 Key。

### 记录哪些信息

复用现有 `GatewayExecution`、媒体请求/回执和用量账单，在需要的位置补充集成模式、凭证引用、双方业务编号、费用来源和账务同步关联。一次执行不要再建立另一套重复的可独立扣费账单。

每次发出请求前，先持久化执行编号；远端请求编号、任务编号后续补录。编号用于关联和重复检查，不把原始提示词、文件或 Key 存进同步记录。

### 验收

测试企业 A/B 同时调用时不会串 Key；用途匹配；平台校验继续使用平台连接；原模式行为通过回归测试。新模式分支可通过测试适配器验证，但生产开关保持关闭。

## 5. 第三批：人民币结算记录与可靠重试基础

### 先完成哪些本地能力

| 能力 | 本批实现内容 |
|---|---|
| 实际费用记录 | 人民币 6 位小数字符串、远端账单编号/版本、待确认或已确认；未确认不当成 0 元 |
| 结算决定 | 保存免费、付费、未付金额及本地账单关联；完整决定不能被重试改写 |
| 远端同步记录 | 保存结算/划转业务编号、规范化请求摘要、重试次数、状态、下次处理时间及远端回执 |
| 待办处理 | 事务内保存待同步事件，后台按租约领取；同编号重复处理不重复过账 |
| 对账记录 | 保存远端流水游标、水位、最近核对时间和差异；未获取数据不是余额 0 |

金额使用既有 Decimal 能力，不新增浮点金额计算。重试框架优先复用项目现有数据库任务和定时补处理方式，不在没有需要时再引入一套队列基础设施。

本批先验证金额守恒、状态转换、去重和恢复；未取得远端真实人民币最终费用，不触发新模式实际扣款。测试中的模拟响应只存在于测试适配器，不提供生产“模拟结算成功”。

### 对话和媒体分别如何接入

- 对话沿用开始检查余额、执行记录和后台扫描的结构；新模式将来按远端确认的实际人民币费用进入本地扣款事务。资金不足沿用欠费记录，不增加请求前预占。
- 图片、视频保留原预占及结转机制；新模式将来替换价格、实际费用来源和远端结算确认，不再乘汇率。
- 本地事务需要将资金变化、账单和待同步事件一起保存，避免钱扣了却没有可重试记录。
- 企业钱包转入/退回暂不改真实过账路径，先准备幂等划转及待办结构；等 N06/N07 可用再接通。

### 验收

覆盖全免费、部分免费、零费用、欠费、重复费用通知、重复结算、进程重启及远端确认丢失。对话无预占，免费权益在实际结算事务中不能被重复消耗。所有新模式资金副作用由启用条件拦住，原模式不发送新增远端扣款请求。

## 6. 第四批：后台可见和可排障

平台管理员在现有算力管理区域查看企业列表及详情，增加开户状态、三类凭证状态、集成模式、最近同步、待处理数量和错误原因；账务列表能按企业、状态、业务编号筛选。

企业管理员只看自己企业的连接和同步状态，不显示完整 Key、服务认证配置或其他企业信息。接入既有设置/算力区域，不另建价格管理页。

操作仅允许恢复原操作，例如重试同一开户单、查询原结算单；不能提供“忽略错误强制成功”“直接改远端余额”。在真实接口尚未接通时，显示未接通，禁用依赖它的按钮，不用示例数据冒充结果。

页面使用现有组件和 TanStack Query，接口 DTO/Zod 在 shared 定义。页面完成后实际启动并做桌面/窄屏检查；只编译通过不算页面验收。

## 7. 哪些等算力平台完成后再接

| 依赖 | 本地先准备 | 后续接通条件 |
|---|---|---|
| N01/N02 开户 | 状态、唯一业务编号、待办、查询/重试界面 | 远端请求响应及凭证交付格式明确 |
| N03 Key 轮换 | 凭证版本和历史任务关联 | 可后续接入，不影响首批基础开发 |
| N04 实际人民币费用 | 金额结构、账单状态、执行关联 | 能返回可信 final/pending 和远端账单版本 |
| N05 结算确认 | 不可变决定、幂等记录及待办 | 免费免扣、付费扣款、查原回执通过联调 |
| N06/N07 充值退回 | 划转记录及状态 | 远端同编号重试不重复增减，未知结果可恢复 |
| N08/N09 余额流水 | 对账游标、差异记录及页面 | 人民币余额和流水同水位，不能只是美元展示值 |
| 原模型/媒体接口调整 | 企业解析器、用途、执行编号 | 服务认证、请求关联和媒体人民币字段确认 |

远端具体路径及版本只留在适配层，不散落到业务模块；加密格式、签名及完整 schema 未定时不写成默认成功的客户端。

## 8. 模块改动范围

| 范围 | 计划 |
|---|---|
| `backend/prisma` | 新增绑定、凭证及同步记录等必要结构，生成新迁移，不覆盖历史迁移 |
| 新 `backend/src/modules/compute-integration` | 绑定、连接解析、状态、待办及远端适配边界，注册到 app.module |
| `backend/src/modules/auth` | 两个现有企业创建入口的后续开户任务挂载点；准备阶段不开真实远端调用，不影响本地注册成功 |
| `gateway`、`conversation`、`digital-employee`、企业任务模块 | 统一连接和执行关联，保留原协议和原模式 |
| `media-config`、`media-gateway`、`setting` | 企业实际调用与平台参数校验的连接分工，媒体预占保持原行为 |
| `compute-credit`、`wallet`、`personal-wallet` | 核对本地金额事务和将来待办接入点；本批不擅自改资金归属或个人兜底政策 |
| `backend/src/shared`、前端算力/设置相关区域 | 共享状态 DTO、查询 hooks、管理员状态与异常展示 |

不是同时重写以上所有模块。先完成绑定和解析器，再逐入口接入、验证，最后加入账务基础和页面，按批次交付。

## 9. 测试、迁移和发布

各批先跑对应单测及必要集成测试，再按范围做后端/前端类型检查与构建。测试使用隔离数据及模拟 Prisma/远端，不访问真实算力账户，不调用模型收费。

涉及并发/唯一约束的正确性，最终还需在隔离 PostgreSQL 环境验证实际事务行为，不能仅凭 mock 单测宣称通过。模拟联调不等于跨平台联调成功。

迁移采用工具生成，先在测试数据库应用，再生成 Prisma Client。新增字段/表尽量采用可兼容旧版的方式，旧账不重算、不批量迁移真实余额、不自动给远端充值。数据库和线上发布在后续实施阶段另列执行清单。

新功能准备完成后可以发布默认关闭的代码，但企业启用必须同时满足：账号及三 Key 已就绪、旧在途账单已处理、资金来源映射已核对、价格和实际费用人民币接口已确认、免费与付费结算及充值退回已通过联调。不能只验证 Key 能调用就切换。

## 10. 交付顺序与未定事项

建议顺序：第一批账号凭证 -> 第二批连接及执行关联 -> 第三批账务记录与待办 -> 第四批页面 -> 真实接口接入和联调。每批提交测试结果和可检查内容，再提醒提交 Git；不自动合并、push 或上线。

第一批就可以开始，不依赖远端在线；涉及未定远端协议只准备本地结构和边界。仍需确认的业务事项是对话欠费补收、个人钱包支付归属、企业停用/删除后的在途账务处理；本批不以猜测规则替代确认，也不因此停止可独立完成的基础开发。
